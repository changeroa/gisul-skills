# 검색 개선과 제한된 자동 발견

Understood as: 54건 비교에서 확인한 검색 실패와 로컬 중복을 고치는 후보를 구현하고,
검색 알고리즘·키워드·호출 정책을 분리해 검증한 뒤 실제 모델 비교를 수행한다.
운영 승격은 기존 행동 변경 gate가 요구하는 근거를 충족할 때만 진행한다.

## 이번 변경

- public `gisul`: 기존 검색 호환 모드, 이름·키워드 순위, 자동/명시 호출 구분,
  검색 commit으로 로드, 같은 스킬의 복수 버전을 구별하는 load_id.
- private `gisul-skills`: 관측된 네 분야의 한영 키워드와 로컬 우선 로더 후보,
  격리된 실행·평가 증거. keywords 변경은 행동 변경으로 취급한다.
- 기존 전역 플러그인과 R2 content는 평가 대상의 기준선으로 유지한다.

## 판정 순서

1. 실제 MCP 호출로 기존 검색 호환, 정확한 이름의 순위, 자동 모드의 수동 전용 제외,
   이름이 같은 다른 source 보존, 안정적 pagination을 검사한다.
2. current 변경 전후의 검색→로드와 동일 URI 재로드를 검사한다. 이전 load_id의
   supporting file은 이전 manifest에 고정되며 제공 불가 버전은 명시적으로 실패해야 한다.
3. 기존 26개 개발 질의에서 원래 키워드/새 키워드 × legacy/순위 모드를 분리한다.
   알려진 실패의 수리율이며 새로운 holdout 정확도로 표현하지 않는다.
4. 모델 비교 전에 source, content, loader, 모델·effort, 사례·예산을 고정한다.
   기존 로더와 제한된 발견 후보를 같은 reader/content에 놓고 비교한다.
   원격 의존 조건과 관련 native 스킬이 있는 조건은 별도로 보고한다.

작업 정확성과 실제 금지 위반을 주 지표로 삼는다. 검색 횟수와 절차 이름은 품질
점수가 아니다. 동일 모델 judge의 의미 판정은 잠정값이며, 사람 평가는 위조하지
않는다. 본문과 keywords 변경을 함께 적용한 묶음의 결과로 개별 효과를 주장하지 않는다.

## 모델 실행 사전 계획

첫 단계는 D01,D02,D05,D07,D08,E02,N03,N05의 8개 기존 개발 사례를 기존 로더와
bounded 로더로 한 번씩, 총 16회 실행한다. 두 조건 모두 같은 후보 reader와
동일한 새 content를 사용한다. 모델은 `gpt-6-astra/max`, 동시 실행은 최대 2,
turn 제한은 240초, 단계의 새 실행 중단 기준은 관측 토큰 1.4M이다. 진행 중인
실행은 종료시킨 뒤 실제 초과 사용량도 기록한다. 격리 위반 즉시 또는 인프라
오류 두 번이면 중단하며, 유리한 결과를 얻기 위한 자동 재시도는 하지 않는다.

첫 단계에서 critical 0, 작업 통과 수 baseline 이상, 평균 비용 130% 이하인
후보만 남은 기존 개발 사례로 확장한다. 미실행 항목은 통과가 아니다.
별도로 native `mandela`를 허용해 D01,E01,N01,N05를 비교한다. 실행 전에 기존
`selective` 정책을 참조군으로 추가해 baseline/selective/bounded 총 12회로 고정한다.
단계 토큰 예산은 900k, 동시 실행은 2이며 나머지 중단 조건은 같다. 이는
기존 로컬 설치를 지운 조건과 섞지 않는다. 이번 후보는 관련 native 절차를
먼저 선택하는 정책이며, 다른 제공자의 동명 스킬을 동일한 패키지로 단정하지 않는다.

이후의 전역 시작 토큰, canonical regression/holdout, 사람 10건 평가는 승격을
위한 다음 단계다. 첫 단계에서 후보가 탈락하면 그 실패를 보고하고 기준을
낮춰 승격하지 않는다. 후보 stdio 실행은 실제 bridge/server의 격리된 release
fixture이며, 운영 Worker 배포나 전체 native 카탈로그 사용 검증과 구별한다.

## 별도로 기록하는 reader 보완

첫 pilot의 reader는 `ed10cd8407b0930a591a12aeef145d2e051de70bda07742047ab614fe28b1f55`
번들로 고정했다. 실행 중 실제 Worker 진단에서 영어 부분 문자열의 오탐
(`hate`가 `whatever`에 일치)을 확인했다. 소스를 보완했지만 진행 중인 번들은
교체하지 않았다. 후속 native 비교와 질의 진단은 영어 단어 경계 보완 버전을
따로 동결해 사용한다. 두 runtime의 모델 결과를 하나의 비교군으로 합치지 않는다.

## Pilot 판정과 확장 동결

16회가 모두 완료됐고 baseline/bounded 각각 8/8 잠정 통과, critical 0이었다.
표준 API 가격으로 환산한 관측 비용 비율은 1.258536으로 1.30 이하이므로,
사전 계획대로 남은 개발 사례 D03,D04,D06,E01,N01,N02,N04,N06,F01,F02를
두 조건으로 실행한다. 모델·effort·loader·content와 첫 pilot의 reader 번들을
유지한다. 새 20회 단계의 토큰 상한은 1.4M, 동시 실행은 2, 다른 중단 조건도
동일하다. reader는 변경 가능한 build 경로 대신 처음 번들의 SHA 경로를 사용한다.

캐시를 제외한 비용 비율은 1.710872, 평균 시간은 61.051→88.802초였다.
따라서 확장 조건 충족은 비용 효율이나 품질 우월성의 확인이 아니다. 실제 청구
금액으로 표현하지 않으며, 캐시 민감도와 같은 모델 judge·사람 평가 0건을 함께
보고한다. native 12회는 reader 보완 버전이므로 별도 표로 평가한다.
