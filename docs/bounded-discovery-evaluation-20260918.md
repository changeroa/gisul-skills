# 제한된 gisul 자동 발견 검증, 2026-09-18

한영 키워드, 자동 호출 가능 여부, 로컬 우선 선택을 평가 브랜치에 구현하고 작업 48회를 실행했다. 알려진 검색 실패와 로컬·원격 중복 읽기는 개선됐지만, 원격 중심 비교의 작업 통과는 두 조건 모두 17/18이고 후보 비용은 17.2% 높았다. 설치된 플러그인과 운영 배포에는 적용하지 않았다. 아래 평가는 개발 방향을 판단하는 실험이며 기존 publication gate를 대체하지 않는다.

## 구현과 실제 연결

공개 reader 후보는 [gisul PR #4](https://github.com/changeroa/gisul/pull/4)에 있다. `automatic` 검색은 사용자 호출 전용 스킬을 제외하고, `explicit`은 포함한다. 정확한 이름과 버전 관리되는 keywords를 우선하며, 영어 단어 중간의 우연한 일치를 제거한다. 기존 클라이언트가 mode를 생략하면 기존 검색 방식을 유지한다.

검색 결과의 commit을 로드에 넘길 수 있고, 로드마다 받은 `load_id`로 supporting files를 읽는다. 같은 URI를 새 버전으로 다시 로드하거나 current를 롤백해도 이전 로드의 파일은 이전 manifest에 고정된다. 선택한 commit을 서버가 제공하지 못하면 본문을 읽기 전에 실패한다.

비공개 후보는 네 스킬의 한영 keywords와 [2,400바이트 로더](../eval/candidates/discovery/bounded/SKILL.md)다. 관련 native 스킬을 우선하고, 원격 발견이 필요하면 후보 다섯 개에서 시작해 빈 결과의 표현 변경 한 번과 본문 한두 개 읽기로 제한한다. 명시적 원격 요청과 원격 사용 거부는 우선한다. 지침의 제한은 모델 정책이며 강제 호출 quota가 아니다.

최종 공개 head `a899af9d8feeb029e0d20cf01a38c16328ebf374`의 CI는 서버 41개와 Worker 35개 테스트, 타입 검사, reader build, Wrangler dry run을 통과했다. 비공개 harness 테스트도 32/32 통과했고 스킬 33개가 유효했다. 한영 키워드 경고는 29개 남아 있어 전체 카탈로그의 검색 개선을 완료한 것으로 보지 않는다.

최종 reader v2로 수행한 모델 비교는 native 조건 12회다. 원격 중심 36회는 v1 결과이므로 CI 성공과 합쳐 v2의 전체 행동 검증이 끝났다고 해석하지 않는다.

새 reader를 설치하지 않고 실제 authenticated Worker에 연결해 검색, 본문 로드, commit과 `load_id`로 고정한 supporting file 읽기를 확인했다. 이는 운영 content에 대한 reader 호환 검증이다. 새 keywords는 아직 R2에 발행하지 않았다. [v2 연결 증거](evidence/bounded-discovery-20260918/live-reader-v2.json)

## 검색 개선의 원인

기존에 실패를 관측한 26개 질의를 같은 MCP 경로로 검사했다. 그중 21개는 목표 스킬이 있는 질의이고 다섯 개는 관련 없는 질의다. 새 문제를 숨겨 둔 holdout이 아니므로 일반 검색 정확도로 표현하지 않는다.

| 메타데이터 / 검색 방식 | 목표 발견 및 상위 5개 포함 | 관련 없는 5개 질의의 반환 |
| --- | ---: | ---: |
| 기존 / 기존 방식 | 8/21 | 0 |
| 기존 / 순위 방식 | 8/21 | 0 |
| 한영 keywords 추가 / 기존 방식 | 21/21 | 0 |
| 한영 keywords 추가 / 순위 방식 | 21/21 | 0 |
| 한영 keywords 추가 / 자동 호출 모드 | 자동 대상 17/17 | 0 |

자동 모드에서는 사용자 호출 전용인 `hate`를 목표로 한 네 질의를 의도대로 제외했다. 탐색 범위의 개선은 keywords 추가에서 나왔으며 순위 변경만으로 생긴 효과가 아니다. 일부 순위는 좋아졌지만 모든 질의의 순위가 개선된 것은 아니다. 단어 경계 보완 버전에서도 위 탐색 범위를 재확인했다. [질의와 결과](evidence/bounded-discovery-20260918/search/summary.json)

기존 메타데이터 대조군은 로컬 immutable release `20260917.5`다. 그 252개 content 파일이 해당 Git commit과 바이트 단위로 같고, content identity가 운영 `20260917.10`과 같음을 별도로 확인했다. 운영을 이전 release로 바꾸지 않았다. [Git 대조 증거](evidence/bounded-discovery-20260918/base-content-proof.json)

## 작업별 모델 비교

모델은 `gpt-6-astra/max`로 고정했다. 두 조건은 같은 새 content와 reader를 사용하며 loader와 작업 지침만 다르다. baseline은 설치된 기존 로더, bounded는 로컬 우선·제한된 원격 발견 후보다. 각 작업은 격리된 새 세션에서 실행하고 정답·rubric·다른 실행의 파일 접근을 차단했다. 의미 평가는 조건 이름을 숨긴 동일 모델 judge의 잠정값이며 사람 평가는 0건이다.

18개 개발 조건에 두 로더를 적용한 36회가 모두 완료됐고, 누락·재시도·인프라 실패는 없었다. [비교 원장과 채점](evidence/bounded-discovery-20260918/remote-v1/comparison.json)

| 설정 | 잠정 통과 | critical | 검색 시도 / 본문 로드 | 평균 비용 환산 | 기존 대비 | 평균 시간 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 17/18 | 0 | 2 / 2 | $0.2360 | 1.00배 | 50.1초 |
| bounded | 17/18 | 0 | 18 / 8 | $0.2765 | 1.17배 | 66.5초 |

검색 시도에는 연결 실패도 포함한다. 두 조건의 미통과는 E01의 동일한 rubric 항목이다. 미노출 평가 문제와 독립 정답 검증을 제안했지만 평가 문제 집합의 사전 동결을 명시하지 않았다. 두 답변을 사람 검토에서 통과로 보더라도 후보의 작업 통과 우위는 생기지 않는다. 비용 상한은 충족했으나 작업 이득을 확인하지 못했고, canonical 회귀·holdout이나 전역 활성화로 진행하지 않았다.

확장은 사전 계획대로 진행했다. Pilot 8개 사례 × 두 조건은 각각 8/8 통과, critical 0, 비용 1.2585배로 1.30배 이하였으므로 나머지 열 사례도 같은 reader로 실행했다. 전체 36회의 캐시 제외 비용은 1.4905배였다. 이전 54회 실험과 reader/content가 다르므로 단순 전후 비용 차이를 loader 개선 효과로 계산하지 않는다.

비용은 실제 계정 청구액이 아닌 고정 API 단가의 비교용 추정치다. 캐시 없는 값도 실제 비용 예측이 아니며 캐시 편향을 확인하기 위한 민감도다. 18개 조건 중 일부는 같은 평가 예제나 HTML을 재사용하므로 독립된 18개 난도의 증거가 아니다. 작업 48회는 2,357,006토큰, 별도의 judge 22회는 240,591토큰을 사용했다. [예산 기록](evidence/bounded-discovery-20260918/budget.json)

실제 자동 질의에는 별도 개선점이 남았다. 정상 연결에서 자동 검색을 시작한 여덟 작업 단계 모두 첫 질의가 길어 결과가 비었고, 짧게 넓힌 두 번째 질의에서 일곱 번 찾았다. 검색은 모든 단어가 맞아야 하는 방식이므로, 다음 후보는 첫 질의부터 짧은 주제어를 쓰게 해야 한다. 이 설명은 관측된 원인의 해석이며 아직 실행하지 않은 새 loader의 비용 절감 수치로 표현하지 않는다. [호출 인자와 결과](evidence/bounded-discovery-20260918/mechanisms.json)

## Native가 있는 조건

관련 native `mandela` 하나를 허용한 D01,E01,N01,N05를 세 조건으로 각각 한 번씩 실행했다. 이 12회는 단어 경계 보완 reader를 사용했으므로 위 remote-only 비교와 합산하지 않는다. [원장과 채점](evidence/bounded-discovery-20260918/native-v2/comparison.json)

| 설정 | 잠정 통과 | critical | 원격 검색 / 로드 | 평균 비용 환산 | 기존 대비 | 캐시 제외 대비 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 3/4 | 0 | 0 / 1 | $0.1760 | 1.00배 | 1.00배 |
| 기존 selective | 3/4 | 0 | 1 / 2 | $0.2565 | 1.46배 | 1.28배 |
| bounded | 4/4 | 0 | 0 / 1 | $0.2327 | 1.32배 | 1.02배 |

D01에서 baseline과 bounded는 native 본문만 읽었고, selective는 native를 읽은 뒤 원격에서도 같은 절차를 검색·로드했다. 총 토큰은 각각 32,089 / 32,348 / 69,196이었다. 명시적 URI 요청 E01은 세 조건 모두 원격을 직접 로드했고, 단순 질문 N01과 원격 거부 N05에서는 모두 원격 호출이 없었다. 후보 content에는 keywords가 추가되어 있으므로 이 실험을 바이트가 같은 패키지의 자동 중복 제거라고 부르지 않는다.

점수 차이는 E01 한 조건에서 나왔다. 세 답변 모두 미노출 평가 문제와 독립 정답 검증을 제안했으나, judge는 baseline/selective가 평가 문제 집합 자체의 사전 동결을 명시하지 않았다고 판정했다. 같은 평가 예제의 rubric에 민감한 결과여서 한 번의 차이를 일반적인 품질 향상으로 해석하지 않는다. 실제 사람의 판단도 필요하다. Native 조건의 비용은 130% 상한을 넘었다. D01의 bounded 입력에는 캐시 할인이 없었던 영향이 크지만, 그 이유로 판정 기준을 캐시 제외 값으로 바꿔 통과 처리하지 않는다.

실행 중 영어 부분 문자열 오탐을 발견했지만 이미 시작한 비교의 번들을 교체하지 않았다. v2의 실제 `hate` 자동 질의는 manual-only `hate`를 제외하고 `nba`를 반환했다. `nba`의 설명에 독립된 단어 `hate`가 있으므로 이 결과는 manual-only 필터 실패가 아니다. v1에서는 `whatever`까지 일치해 `modelchk`와 `readchk`도 반환했다.

소스·content·loader·시나리오·모델을 고정한 격리는 확인했지만, 설계자와 채점 모델의 독립성을 확보한 최종 인증은 아니다. `mandela` 감사에서 기존 개발 문제 재사용, rubric 설계자와 검증자의 결합, 점수가 높은 기준선의 천장 효과를 제한으로 남긴다. 검색 성공률이나 호출 감소를 사용자 작업 품질의 대리 정답으로 삼지 않는다.

## 운영과 다음 판단

운영 release와 설치 플러그인은 [기존 배포 기록](worker-r2-deployment-20260917.md)의 상태를 유지한다. 운영 Worker source는 `132cadd6ddc27f3f8dde763da8e1b67fec34dc96`, content는 `e6c7245951993a45cb22e523b5aa49ad450ce172` / `20260917.10`이다. 전역 자동 검색을 활성화하거나 새 content를 발행하지 않았다. 이번 합성 실행을 Langfuse 운영 trace 또는 E14 하루 중복 검사에 섞지 않았다.

다음 후보의 출발점은 개선된 검색과 native 우선 선택이다. 자동 호출을 늘리는 것 자체는 목표가 아니다. 실제 업무에서 절차 누락으로 재작업한 사례를 별도로 모아 작업 성공의 이득을 확인해야 한다. 같은 개발 예제를 더 돌려 유리한 점수를 고르는 대신, 후보를 동결한 뒤 [기존 승격 기준](../eval/README.md)의 canonical 회귀·holdout, 전역 초기 토큰 비교, 사람 10건 판정을 수행해야 한다. 이번 결과는 그 미실행 항목의 통과를 주장하지 않는다.

현재 처분은 **수정 후 재평가할 후보로 보존**이다. 다음 개발 실험에서는 실제 실패 사례의 작업 완료가 개선되는지 먼저 판단하고, 유망한 후보에 승격 검증 비용을 쓴다. 이는 실험 우선순위 판단이다. 공식 승격은 여전히 critical 증가 0, holdout 회귀 없음, 누락된 채점 없음, baseline 이상의 작업 통과, 평균 비용 130% 이하, judge 버전 기록과 실제 사람 10건의 판정 일치가 필요하다. 이 조건을 코드에서 완화하지 않았다.
