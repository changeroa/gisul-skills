선정된 저장소에서 기존 실행·검증 경로를 먼저 읽고, `templates/project-runtime/`의 계약을 맞춰 적용한다. 적용 대상이 정해지지 않았으면 템플릿 예제만 검증한다.

- `runtime.config.mjs`를 프로젝트의 실제 서비스 명령·health 응답·로그인 API에 맞춘다. 계정 식별자는 로그인 응답에서 읽으며 역할이나 이메일로 추정하지 않는다.
- 기존 패키지 관리자·lockfile·테스트 계정 공급 경로를 유지한다. worktree마다 포트를 분리하고 생성물은 `.agent-runtime/`에 둔다.
- `ensure-ready`를 두 번 실행해 PID 유지, `reused: true`, 두 번째 실행 5초 미만을 확인한다. 서비스를 재시작할 필요가 있는 변경만 명시적으로 재시작한다.
- 합의된 사용자 흐름을 YAML로 작성하고 실제 결함 재현과 수정 상태에 같은 검증을 실행한다. 예제 통과를 실제 제품 검증으로 보고하지 않는다.
- 루트 지침은 두 스크립트와 결과 위치를 가리키게 하고, 하위 지침은 해당 계약 원본을 가리키게 한다. 완료 근거는 실행한 프로젝트·결과 JSON·증빙 경로다.

템플릿의 전체 설정·실행 계약은 `templates/project-runtime/README.md`를 읽는다. 이 후보를 운영 스킬로 배포하는 일은 별도의 평가·승격 조건을 따른다.
