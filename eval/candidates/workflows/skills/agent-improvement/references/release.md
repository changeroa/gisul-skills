# 배포와 관찰

- 운영 반영이 요청·위임된 범위인지 확인한다. 분석 요청만으로 stable을 수정하지 않는다. 이미 허용된 범위의 작업을 다시 승인받도록 강제하지 않는다.
- 후보 diff, 기준·후보 release, dataset/evaluator 버전, 비교 결과, 회귀 여부와 복구 대상을 갖춘다. 초기 운영은 검토된 후보를 승격하고, 이후 자동 승격 범위는 별도 운영 정책을 따른다.
- gisul의 실제 배포 기능을 확인한다. stable/candidate, 버전별 읽기, atomic 전환이 있다고 가정하지 않는다. 미지원이면 필요한 구현을 명시한다.
- 정식 원본에서 검증된 immutable release를 만들고 지정된 production 서빙 대상을 변경한다. 동일 스킬을 여러 편집 원본에 따로 수정하지 않는다.
- 진행 중 세션이 읽던 지침을 자동으로 교체하지 않는다. 새 세션에서 정확한 release와 reference digest를 읽는지 검증한다.
- 세 기기의 SSH·HTTP·브리지 경로가 의도한 release를 조회하는지 확인한다. 내용 무결성과 실제 작업의 행동 변화를 별도로 확인한다.
- 해당 release의 운영 trace를 기존 조건과 비교한다. 사용자 결과·중요 회귀·재작업·컨텍스트 비용을 확인하고, 문제가 생기면 근거를 남겨 이전 버전으로 복구한다.
- 실제 배포 release와 사용 경로, 평가 결과, 남은 관찰을 보고한다. 이슈 완료는 해당 작업에 합의한 운영 관찰 조건까지 충족했을 때 수행한다.
