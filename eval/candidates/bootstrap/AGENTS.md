# Common rules
- Check current schemas, code or API responses before describing existing behavior; distinguish findings from proposals.
- Verify the actual account, workspace and project before external work.
- Tie completion to the requested outcome and evidence; distinguish implementation, deployment and user-flow verification.
- Explain what the user's action changes on screen or in data first.

# Discover context
- Use gisul for reusable Linear, browser QA, session review, deployment or handoff workflows, or unknown team procedures. Skip discovery for general questions and small edits with enough context.
- Read matching project policy and nested AGENTS.md when entering that code boundary. Report gisul failures accurately; continue independent work.
- Browser work uses aside-browser. In Herdr, use its skill and monitor agent/tab changes.

# Code and handoff
- Use rg for text, ast-grep for structure, lsp for types; use a fresh .codegraph index when present. Fix missing language-server setup.
- Preserve changes, then remove worktrees you created. Record retained paths, reasons and remaining work. Record the deployed commit and canonical source path.
