# GitHub 반영 후 배포

코드 변경의 기본 완료 흐름은 **구현·검증 → 커밋 → GitHub push → PR 생성·갱신 및 원격 확인 → 배포 → 배포 결과 기록**이다. 배포 후에 push나 PR을 미루지 않는다. 로컬 커밋만 있는 상태는 GitHub 반영 완료가 아니다.

## 1. 저장소와 변경 범위를 확인한다

- 실제 GitHub 저장소, 원격 주소, 기본 브랜치, 현재 브랜치, 기존 PR, 작업 트리 변경사항을 확인한다. 저장소 이름 변경·이전이 있으면 GitHub가 반환하는 정식 저장소를 사용한다.
- 기본 브랜치와의 차이를 확인한다. 현재 작업에 필요한 의존 변경을 포함하되, 미커밋 사용자 작업·다른 작업자의 변경·비밀정보를 일괄 추가하지 않는다.
- 이미 진행 중인 PR이 같은 작업을 다루면 갱신한다. 관련 없는 기존 PR에 끼워 넣지 않는다. 필요한 경우 의존 PR과 후속 PR로 나누고 관계를 설명한다.
- 배포 담당 작업이나 다른 에이전트가 있으면 담당 커밋과 대상 환경을 맞춘다. 다른 작업자의 브랜치·worktree를 임의로 전환하거나 정리하지 않는다.

## 2. 검증된 변경을 GitHub에 먼저 반영한다

변경에 필요한 검사와 저장소 필수 검사를 수행하고, 의도한 파일만 커밋한다. 그 커밋을 GitHub 작업 브랜치에 push한 뒤 PR을 생성하거나 기존 PR에 반영한다. push·PR 생성 요청의 성공 메시지만으로 완료를 단정하지 말고 원격 브랜치 SHA와 PR의 head SHA·base를 읽어 확인한다.

PR 제목은 사용자에게 달라지는 결과를 짧게 나타낸다. 본문은 문제와 최종 동작을 먼저 설명하고, 관련 변경·검증 결과·남은 한계·배포 상태만 적는다. 구현, 검증, 게시, 배포 완료를 구분한다. 범위가 바뀌면 제목과 본문도 최종 변경에 맞게 고친다. 저장소 PR 템플릿이 있으면 따른다.

여러 줄 본문은 도구의 구조화된 인자나 정확한 텍스트 파일과 `--body-file`로 전달한다. 본문을 셸 명령 문자열에 보간하거나 개행을 문자 `\n`으로 게시하지 않는다.

저장소에서 명시적으로 정한 직접 반영 방식이 적용되면 그 방식을 따른다. 이 경우에도 GitHub의 대상 브랜치에 정확한 커밋이 반영됐는지 확인한 뒤 배포한다. PR이나 필수 검사를 편의상 생략하는 근거로 삼지 않는다.

## 3. 배포 직전 반드시 확인한다

아래가 확인되기 전에는 새 변경을 배포하지 않는다.

- 배포할 소스 커밋이 GitHub 원격에 존재한다. PR 기반 작업이면 해당 변경이 올바른 PR에 포함돼 있다.
- 검증한 소스와 배포할 소스가 같다. push 뒤 수정했으면 필요한 검증·커밋·push·PR 갱신을 다시 완료한다.
- 저장소의 필수 CI·리뷰·머지 정책을 충족한다. 미완료·실패 검사를 통과했다고 쓰지 않는다.
- 배포 대상의 프로젝트·서비스 이름, 계정, 환경, 도메인과 설정 파일을 확인했다. 기본 배포 스크립트가 의도한 환경을 가리킨다고 추정하지 않는다.
- 작업 트리에 섞인 미커밋 파일이 빌드에 들어가지 않는다. 필요하면 GitHub에 반영된 SHA의 깨끗한 checkout/worktree에서 빌드한다.

기본 브랜치 배포 정책이면 승인된 방식으로 머지된 최종 커밋을 사용한다. PR 브랜치 배포가 허용되면 원격에 반영된 PR 커밋을 사용할 수 있다. 이 스킬은 PR 머지·배포·강제 push 권한을 새로 부여하지 않는다. 이미 받은 승인은 다시 묻지 않으며, 필요한 승인이 없으면 검증과 검토 가능한 PR 준비를 마친 뒤 해당 행동만 요청한다.

인증·네트워크·push·PR 등록 실패로 GitHub 반영을 확인하지 못하면 배포를 멈추고 원인과 남은 작업을 알린다. 원격 반영 여부가 불확실한 응답은 먼저 조회해 확인하고, 중복 PR 생성이나 무분별한 강제 push로 해결하지 않는다.

## 4. 배포와 기록을 연결한다

배포가 승인된 범위에 있으면 GitHub 반영 확인 후 진행한다. 실제 배포 커밋과 서비스 버전·대상 URL을 기록하고, 가능한 health·에셋 또는 빌드 식별자로 배포 결과를 확인한다. 소스가 달라졌거나 다른 작업의 배포가 진행 중이면 대상을 다시 조정한다.

PR 본문이나 저장소의 배포 기록에 실제 결과를 갱신한다. 배포 후 문서만 추가한 커밋은 배포 소스 커밋과 구분하고 GitHub에도 push한다. 이미 GitHub에 있는 이전 커밋으로 롤백할 때는 새 PR을 억지로 만들지 않고 대상 커밋과 복구 결과를 기록한다.

최종 응답에는 **PR 링크, GitHub 반영 상태, 배포 여부와 실제 배포 커밋**을 짧게 전달한다. 배포하지 않았다면 완료한 범위와 남은 이유를 정확히 쓴다.

임시 worktree는 필요한 변경과 증적을 정식 경로에 보존하고 사용 중인 작업이 없음을 확인한 뒤 제거한다. 남겨야 하면 경로·이유·제거 조건을 기록한다.

## 완료 판단 예시

- 로컬 테스트와 커밋만 완료: push와 PR 반영을 먼저 한다. 배포 완료로 끝내지 않는다.
- PR을 만든 뒤 코드를 수정함: 새 커밋의 검증과 push, PR head 확인을 다시 한 뒤 배포한다.
- push 실패 후 “일단 배포”: GitHub 반영이 확인될 때까지 배포하지 않는다.
- PR과 필수 검사가 완료됐고 배포가 이미 승인됨: 불필요한 재승인 없이 해당 원격 커밋을 배포한다.
