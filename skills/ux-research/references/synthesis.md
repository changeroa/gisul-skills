# 증거에서 해석과 결정으로

## 분석 가능한 자료인지 확인한다

자료의 수집 목적·동의 범위·실제 대상·기간·프로토콜 버전과 누락 구간을 확인한다.
실제 기록이 없으면 가설·분석 계획만 작성한다. 예시 데이터를 실제 연구 결과로 채우지 않는다.
파일럿·실제 세션·에이전트 실행·팀 의견을 서로 다른 자료 유형으로 분리한다.
동의된 도구·접근 범위 안에서만 분석하고 비식별화되지 않은 자료를 무단 전송하지 않는다.

## 원자적 관찰을 만든다

기존 기록 형식에 다음 필드를 연결한다. 불필요한 개인정보는 제거한다.

```text
관찰 ID / 참여자 코드 / 역할·경험·환경
세션·과업 ID / 프로토콜 버전 / 제품 버전
기록 위치·시점 / 관찰 행동·자기 보고·연구자 해석 구분
한 가지 사건 또는 생각 / 개입·중단·기술 문제
코드 목록 / 중복·연결 관찰 ID / 해석상 한계
```

- 원문을 길게 복제하지 않고 필요한 내용을 짧게 정리한다. 인용은 실제 기록과 동의가 있을 때만 쓴다.
- 한 발언을 분해해도 원래 맥락을 잃지 않도록 원자료로 되돌아가는 위치를 유지한다.
- 부정, 조건, 시간, 비교 대상이 요약에서 뒤집히거나 없어지지 않게 검토한다.
- 기억에 의한 재구성은 그 한계를 표시하고 정확한 인용문으로 만들지 않는다.
- 한 사건을 여러 관찰자가 기록했거나 여러 코드에 배치했으면 같은 관찰의 연결임을 표시한다.

## 테마와 negative case를 함께 만든다

1. 초기 코드의 의미·포함·제외 기준을 짧게 적고 실제 자료에 적용한다.
2. 비슷한 관찰을 묶되 같은 단어를 썼다는 이유만으로 같은 문제로 합치지 않는다.
3. 역할·맥락·시점별로 다시 보아 묶음이 유지되는지 확인한다.
4. 테마에 맞지 않는 사례, 아무 문제 없이 수행한 사례, 반대 설명을 적극적으로 찾는다.
5. 모순이 표본·경험·과업·프로토콜 차이로 설명되는지 조사한다.
6. 설명되지 않는 차이는 제거하지 말고 불확실성과 후속 질문으로 남긴다.
7. 다른 검토자가 중요한 테마·반례의 기록을 확인하게 하거나 검토 한계를 명시한다.

다른 해석을 하나로 합의시켰다는 사실만으로 객관성이 입증되지는 않는다.
AI가 만든 코드·요약은 원자료와 대조한다. 생성된 설명은 관찰로 승격하지 않는다.
연구자의 첫 가설을 지지하는 기록만 뽑지 않는다. 실패한 가설도 판단 근거로 남긴다.

## 빈도·영향·확신을 분리한다

- 단어 빈도, 발언 수, 사건 수, 해당 경험을 한 고유 참가자 수를 구분한다.
- 참가자별 과업 노출·기회가 다르면 같은 분모로 단순 비교하지 않는다.
- 도움 후 완료를 무도움 성공과 합치지 않고 결측·중단·제외를 표시한다.
- 드물어도 안전·데이터 손실 등 큰 영향이 있으면 별도로 다룬다.
- 주관적 중요도·제품 위험·수정 비용을 빈도 숫자에 숨기지 않는다.
- 작은 정성 표본의 관찰 건수는 표본 안의 사실이다. 전체 비율·인과효과로 확대하지 않는다.
- 실측 성공률도 정의·분자·분모·조건·불확실성을 갖춘 경우에만 제시한다.
- 정량과 정성이 다르면 어느 집단·기간·상황·척도를 본 것인지 먼저 비교한다.

확신은 자료 적합성·추적성·독립 증거·반례 설명 여부로 서술한다.
근거 없이 점수나 신뢰구간을 생성하지 않는다. 계측되지 않은 값은 미측정으로 남긴다.

## 발견을 결정 가능한 형태로 작성한다

```text
발견 ID / 연결된 질문·결정
대상·조건 / 관찰 사실과 기록 위치
해석 / 반례·대체 설명 / 근거 수준·한계
예상 영향 / 권고·대안 / 아직 검증하지 않은 가정
결정·담당·시점 / 후속 행동·측정 / 재검토 조건
```

권고는 관찰에서 논리적으로 이어져야 하지만 관찰 자체와 같은 것은 아니다.
참가자의 해결책 요청 뒤 목표·제약을 확인하고 구현 대안을 비교한다.
요약은 중요한 결정을 먼저 제시하되 표본 편향·미답 질문·상충 증거를 숨기지 않는다.
영상·인용은 동의 범위를 따르고 맥락을 잘라 과장하지 않는다.
공유용 persona·여정에도 관찰된 부분과 가정·빈 구간을 구분한다.

## 후속 측정과 연구 기억

채택·보류·추가 연구의 이유를 남기고 권고가 실제 결정에 반영됐는지 확인한다.
개선 전 기준선, 개선 후 비교 조건, 관찰할 행동·지표, 부작용과 판정 시점을 정한다.
QA는 구현·동작을, 실제 연구는 인간의 이해·행동을 검증하도록 연결한다.
효과 자료가 아직 없으면 “결정됨·효과 미확인”으로 남긴다.
결론에 연구 시기·제품 버전·대상·맥락을 붙여 영구적인 사용자 진실로 취급하지 않는다.
중요한 제품·고객·업무 변화나 반례가 생기면 기존 결론과 다음 질문을 함께 갱신한다.
