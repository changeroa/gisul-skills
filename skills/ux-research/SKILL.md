# UX 연구: 질문에서 결정과 재측정까지

제품 결정을 가로막는 불확실성을 적합한 증거로 줄인다.
**결정 → 모르는 것 → 질문 → 방법 → 모집·동의 → 세션 → 디브리프 → 분석 → 결정·측정**을 하나의 루프로 운영한다.
요청된 단계부터 시작하되 앞 단계의 근거를 확인하고, 다음 결정까지 인계한다.
모든 요청에 신규 모집이나 전체 연구를 강제하지 않는다. 기존 문서와 연구 기록을 재사용한다.

## 1. 실행 범위와 증거 경계를 정한다

- 요청이 계획, 진행 지원, 실제 세션, 기존 자료 분석 중 무엇인지 구분한다.
- 제품 결정, 대상 사용자·과업, 결정 시점, 현재 자료, 접근·연락·녹음 권한을 확인한다.
- 자료가 없으면 계획·가설·검증 질문만 낸다. 실제 발견, 참여자 반응, 연구 완료로 보고하지 않는다.
- 에이전트의 UI 탐색·휴리스틱 평가·가상 persona 실행은 인간 사용자 연구가 아니다.
- 인간의 발언·감정·심리·선호·성공률을 생성하거나 에이전트 결과에서 추정하지 않는다.
- 표정·몸짓·시선에서 정직성이나 마음 상태를 판정하지 않는다. 관찰 행동과 확인된 자기 보고를 구분한다.
- 연구 계획 승인을 참가자 연락·모집 게시·설문 발송의 승인으로 확대하지 않는다.
- 외부 모집·발송은 대상, 채널, 내용, 비용 범위에 대한 별도 승인이 있을 때만 실행한다.
- 승인이 없으면 자료와 실행안을 준비하고 해당 단계만 미실행으로 남긴다.
- 제품 변경·배포·실거래도 이 스킬 자체로 허용되지 않는다.

## 2. 결정에서 질문을 도출한다

기존 결정을 찾아 아래를 간결하게 기록한다. 팀이 원하는 답을 연구 목표로 삼지 않는다.

| 항목 | 기록할 내용 |
| --- | --- |
| 결정 | 무엇을 선택·변경·유지할지, 누가 언제 결정할지 |
| 모르는 것 | 현재 근거로 답할 수 없는 사용자·과업·맥락 |
| 가설 | 가능한 설명과 이를 반박할 관찰 |
| 질문 | 어떤 증거가 있으면 결정이 달라지는지 |
| 범위 | 대상·상황·기간과 이번에 답하지 않을 것 |

연구 질문과 참여자에게 할 질문을 분리한다.
“이 기능이 좋은가?” 대신 최근 실제 사건, 목적, 행동, 막힌 지점과 우회 방법을 묻는다.
답변이 어떤 결정에도 쓰이지 않는 질문은 제거하거나 보류한다.
질문이 늘어나면 핵심 결정에 필요한 것부터 우선하고 후속 질문은 별도 목록에 남긴다.

## 3. 질문에 맞춰 방법과 표본을 선택한다

방법·표본을 설계하거나 검토할 때 `references/method-selection.md`를 읽는다.

- 맥락·동기·언어·우회는 인터뷰와 관찰, 특정 과업 수행은 사용성 테스트로 탐색한다.
- 규모·빈도·분포·변화는 정의된 지표와 적합한 표본으로 측정한다.
- 정성은 이유와 새로운 문제를 탐색하지만 모집단 비율을 자동으로 추정하지 않는다.
- 정량은 분포와 차이를 보여 주지만 행동의 이유나 인과를 자동으로 설명하지 않는다.
- 한 방법에서 두 종류 자료가 나올 수 있다. 방법 이름 대신 실제 수집·분석 설계를 본다.
- 후보마다 얻을 증거, 못 얻는 증거, 대상 적합성, 제약과 비용을 비교한다.
- 편의·자발적 참여·기존 이용자 중심 모집의 편향과 빠진 집단을 기록한다.
- 고정 인원수를 모든 연구의 충분성 기준으로 삼지 않는다. 목적·차이·위험·정밀도로 정한다.
- 통계적 주장은 측정 정의·분모·표본·불확실성·분석 계획이 뒷받침할 때만 한다.
- 종료·추가 수집 조건을 미리 정한다. 반복 답변만으로 모든 역할·예외의 포화를 선언하지 않는다.

## 4. 적합한 사람과 안전한 운영을 준비한다

모집 기준은 인구통계만이 아니라 질문에 답할 실제 행동·경험·역할·환경으로 정한다.
포함·제외 조건, 모집 경로, 필요한 집단별 구성과 그 이유를 기록한다.
조건이 다른 참가자를 만나면 자료의 용도를 분리하고 원래 대상의 증거로 섞지 않는다.
노쇼·일정 변경·대체 참가자·언어·접근성 지원을 고려하되 불필요한 개인정보를 받지 않는다.

세션 전에 다음을 확정한다.

- 목적, 진행 방식·시간, 자발적 참여, 질문 건너뛰기와 중단·철회 경로.
- 녹음·화면 공유·인용·관찰자·보고 대상별 동의 범위와 거절 시 가능한 대안.
- 보상 조건·시기와 중도 종료 시 처리. 긍정 응답이나 과업 성공에 보상을 연계하지 않는다.
- 원자료·연락처의 접근권한, 보관 위치·기간, 삭제 책임과 처리 방식.
- 철회 시 식별 가능한 자료·파생 요약의 삭제 범위와 이미 익명 집계된 자료의 회수 한계.
- AI 전사·요약을 포함한 외부 처리 도구의 사용 허용 여부와 데이터 전송 범위.

동의하지 않은 처리는 실행하지 않는다. 기밀이나 완전 삭제를 지킬 수 없으면 약속하지 않는다.
참가자 코드를 쓰고 연락처·동의 기록과 분석 자료를 분리한다.
도구·자료·원격 연결·기록 저장과 세션 간 초기화를 점검하고 실패 시 대체안을 준비한다.
동료 리허설은 절차 검증이다. 본 연구 참여자나 실제 발견으로 집계하지 않는다.

## 5. 유도하거나 대신 해결하지 않고 진행한다

세션 설계·진행 지원에는 `references/facilitation.md`를 읽는다.
진행자·기록자·관찰자의 역할을 정하고, 관찰자 질문은 정해진 시점에 받는다.
단독 운영이라면 기록·주의력 손실과 보완책을 명시한다.

1. 동의·중단권·기록 상태를 확인하고 사람의 능력이 아닌 제품·경험을 조사함을 설명한다.
2. 가벼운 사실 확인으로 시작해 최근 경험 또는 핵심 과업으로 이동한다.
3. 목표와 상황을 제시하되 정답 버튼명·클릭 경로·기대 평가를 알려주지 않는다.
4. 침묵과 시행착오를 허용하고 중립적으로 추가 설명을 요청한다.
5. 참여자를 가르치거나 제품을 방어하지 않는다. 관찰을 위해 불편·위험을 강요하지도 않는다.
6. 사전 개입 기준에 따라 돕거나 중단하고, 시점·내용·이유를 기록한다.
7. 추가 의견과 질문을 받고 종료·보상·철회 연락 경로를 안내한다.

무도움 완료, 도움 후 완료, 과업 미완료, 기술 장애, 중단을 분리한다.
프로토타입 고장으로 인터뷰로 바꾸면 모드 변경을 기록하고 원래 검증은 미확인으로 남긴다.
참여자 발언은 자기 보고다. 연구자가 실제로 관찰한 행동과 합치지 않는다.
민감정보 노출·불편·중단 요청이 있으면 수집을 멈추고 동의 범위에서 재개 또는 종료한다.
연구 목적보다 참여자의 안전·존엄과 철회 의사를 우선한다.

## 6. 세션 직후 디브리프로 수집 품질을 교정한다

- 각 관찰자가 사실과 의문을 먼저 독립적으로 적은 뒤 비교한다.
- 참여자 발언·행동, 진행자의 개입, 팀의 해석을 나눠 검토한다.
- 녹음·노트의 누락, 모집 적합성, 질문 유도, 도구 실패와 새로운 질문을 확인한다.
- 불일치는 합의로 지우지 말고 기록 위치·맥락을 다시 확인한다.
- 다음 세션에서 바꿀 내용, 이유, 프로토콜 버전과 적용 시점을 기록한다.
- 프로토콜이 바뀐 자료를 무조건 합치지 않는다. 비교 가능 범위와 제외 이유를 남긴다.
- 중간 공유는 잠정 발견으로 표시한다. 디브리프의 인상이나 다수결을 최종 분석으로 쓰지 않는다.
- 정성 수집의 조정을 실험의 임의 조기 종료·표본 변경으로 일반화하지 않는다.

## 7. 근거를 추적하며 패턴과 반례를 분석한다

실제 자료를 분석할 때 `references/synthesis.md`를 읽는다.
원자료 → 원자적 관찰 → 코드 → 테마 → 해석 → 권고의 연결을 유지한다.
각 관찰에 참여자 코드, 역할·맥락, 세션·과업, 프로토콜 버전, 기록 위치·시점을 붙인다.
관찰 행동·자기 보고·연구자 해석을 구분하고 개입·누락·기술 문제를 함께 남긴다.

- 한 기록에는 하나의 생각·사건을 담고 원자료의 부정·조건·맥락을 보존한다.
- 같은 사건의 복수 기록·다중 코딩은 중복 표시한다. 독립 참가자 수로 부풀리지 않는다.
- 반복뿐 아니라 negative case, 즉 패턴에 맞지 않는 반례를 적극적으로 찾는다.
- 모순은 역할·환경·경험·과업 조건별로 조사하고 설명되지 않은 차이는 남긴다.
- 드물어도 피해가 큰 문제는 빈도가 낮다는 이유로 제거하지 않는다.
- 정량·정성이 충돌하면 대상·기간·측정 정의·계측·모집 차이부터 확인한다.
- 근거가 부족한 설명은 가설로 유지한다. 가상의 발언이나 빈 자료를 생성해서 메우지 않는다.
- AI 코딩·요약은 실제 기록과 대조하고 수정한다. 자동 요약을 독립 증거로 세지 않는다.

## 8. 발견을 결정과 측정으로 닫는다

청중이 결정할 수 있는 요약과 세부 근거를 분리하되 핵심 한계를 요약에서 빼지 않는다.
각 발견은 아래 내용을 포함하고 기존 이슈·연구 기록의 형식에 맞춘다.

- 답하려던 질문과 결정, 실제 대상·상황·수집 방법·기간.
- 관찰 사실과 근거 위치, 해석, 반례·대체 설명, 확신의 이유와 한계.
- 사용자·업무 영향, 권고 또는 대안, 아직 검증되지 않은 가정.
- 채택·보류·추가 연구 결정, 담당자·다음 행동·확인 시점.
- 효과를 볼 지표·행동, 기준선·비교 조건·부작용과 재검증 방법.

권고의 채택과 효과 입증은 다르다. 결정권자의 확인 없이 제품 정책 확정으로 쓰지 않는다.
정성 관찰만으로 ROI·전환율 개선·인과효과를 만들지 않는다.
개선 후 같은 대상·과업·조건의 비교 가능성을 확인하고 변화한 조건도 기록한다.
제품·고객·업무 환경이 달라지면 이전 결론을 다시 열고 다음 미답 질문으로 루프를 잇는다.

## 9. 기존 QA와 연결하고 완료 범위를 보고한다

- 재현 가능한 UI·동작 결함의 실행 검증은 `exploratory-ux-qa` 또는 `browser-e2e-review`에 맡긴다.
- 그 스킬의 브라우저 조작·HAR·상태 전환·fixture 절차를 여기서 복제하지 않는다.
- QA의 미확인 사용자 해석은 연구 질문으로 받는다. QA 통과를 인간 이해·만족의 증거로 쓰지 않는다.
- 구현·저장·복구의 정확성은 QA로, 사람의 이해·행동 변화는 실제 연구로 구별해 확인한다.
- 모집단 규모·효과는 적절한 정량 설계로 검증한다. 작은 연구의 성공 사례로 대체하지 않는다.

최종 상태를 `계획 / 수집 중 / 분석 완료 / 결정 대기 / 결정됨·효과 미확인 / 후속 측정 완료`처럼 명시한다.
실제로 수행한 단계, 사용한 자료, 미답 질문, 한계와 다음 행동을 구분한다.
자료가 없거나 실행이 막혔다면 계획·가설만 전달하고 부족한 조건을 구체적으로 남긴다.
세션 수나 보고서 발행만으로 완료를 선언하지 않는다. 요청된 산출물과 근거 연결을 확인한다.
