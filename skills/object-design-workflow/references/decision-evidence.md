# 결정과 증거 기록

이 양식은 필요한 항목만 사용하는 작업 도구다. 모든 프로젝트에 별도 문서나 회의를 요구하지 않는다. 기존 issue·작업 기록에 포함해도 된다.

## 1. 한 반복의 최소 기록

```text
목표/계약:
현재 코드 revision / 환경 / 관찰 날짜:
확인된 사실:
미결정 또는 고위험 가정:
틀렸을 때 영향:
현재 변형 / 예상 미래 변화:
품질 시나리오와 수용 기준:
선택한 작은 실행 경로:
검토 대안과 선택 이유:
권한·자원·시간 예산:
중단 또는 전환 조건:
실행한 검사와 관찰:
미검증 경계:
모델 갱신·폐기 / 대응 revision / 검증 날짜:
결정 / 남은 위험 / 다음 행동:
```

서로 영향을 주는 driver는 함께 검토한다. 한 결정을 여러 기록에 복제하기보다 권위 있는 기록 하나에서 관련 시나리오를 연결한다.

## 2. 품질 시나리오를 실제 결정으로 연결하기

불충분한 표현: '변경에 유연해야 한다.'

실행 가능한 표현을 만들려면 다음을 정한다.

- 어떤 종류의 변경이 현재 요청되었는가?
- 허용된 수정·검증·배포 범위는 어디까지인가?
- 대표 변경을 적용할 환경과 담당은 누구인가?
- 예상 비용을 지지하거나 반박할 관찰은 무엇인가?
- 실험 후에도 알 수 없는 규모·변형은 무엇인가?

가용성 시나리오도 '오류가 안 난다' 대신 실패 자극, 감지, 허용 응답, 남은 상태와 복구 종료를 정한다. 로컬 저장 성공과 외부 효과 완료를 같은 상태로 표시하지 않는다.

수치는 계약과 현재 근거에서 결정한다. 예시 숫자를 성능 목표나 수정 시간의 보편 법칙으로 복사하지 않는다.

## 3. 작은 반복의 범위를 고르는 질문

1. 이 가정을 틀리게 만들어 볼 가장 저렴한 실험은 무엇인가?
2. 어느 경계를 생략하면 실험이 핵심 위험을 보지 못하는가?
3. 전체 기능 대신 하나의 완결된 행동으로 줄일 수 있는가?
4. 성공만 확인하면 놓칠 실패·복구 상태는 무엇인가?
5. 결과가 불명확하면 추가 조사, 다른 실험, 보류 중 무엇을 할 것인가?

격리된 실험은 기술 질문 하나에 답할 수 있다. 여러 driver의 결합 가능성은 통합된 경로에서 별도로 확인해야 한다. 둘을 같은 증거 수준으로 기록하지 않는다.

## 4. 증거 수준과 날짜

- **확인된 사실:** 읽은 계약·설정·코드와 적용 범위를 적는다.
- **실행 결과:** 실제 수행한 명령·환경·revision·날짜와 결과를 적는다.
- **제안:** 수행할 수 있지만 아직 실행하지 않은 절차다.
- **미검증:** 현재 자료나 환경으로 판단하지 못한 범위다.
- **차단:** 빠진 권한·입력·자원과 재개 조건을 명시한다.

파일 수정일이나 화면 캡처일만으로 내용의 현재성을 증명하지 않는다. 모델의 마지막 검증이 과거 revision에만 해당하면 현재 모델 일치는 미검증이다. 코드가 바뀌지 않았더라도 외부 서비스·데이터·구성이 바뀌면 증거 적용 범위를 재판단한다.

## 5. 중단 기준을 쓰는 방법

- 수용할 근거를 확보하면 더 정교한 모델이나 패턴을 위해 반복을 늘리지 않는다.
- 예상과 다른 결과가 핵심 가정을 반박하면 설계 변경을 검토한다.
- 동일 실패를 반복하고 새 정보가 없으면 다른 실험이나 입력을 선택한다.
- 권한과 안전 조건이 충족되지 않으면 실행을 멈추고 필요한 최소 입력을 요청한다.
- 예산 종료를 성공으로 바꾸어 보고하지 않는다. 결과와 남은 불확실성을 전달한다.
- 결론에 반하는 증거를 숨기거나 테스트 범위를 줄여 완료 상태를 만들지 않는다.

## 6. 모델 갱신 점검

- 모델은 현재 구현, 가설 또는 선택하지 않은 대안 중 무엇인가?
- 어떤 사용자 행동과 결정을 설명하기 위한 것인가?
- 코드와 다른 책임·상태·호출 순서가 남아 있는가?
- 차이가 의도된 요구 변경인지 오래된 문서인지 확인했는가?
- 대응 revision과 검증 날짜가 실제 확인 범위에 맞는가?
- 유지 가치가 낮으면 제거하고 코드나 짧은 결정 기록으로 대체할 수 있는가?

중요한 경계와 선택 이유는 유지하되 모든 내부 호출을 문서와 이중 관리하지 않는다. 다이어그램이 없어도 결정과 실행 결과를 이해할 수 있으면 형식을 추가하지 않아도 된다.
