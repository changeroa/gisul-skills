# 입력과 명령의 의미 설계

무엇을 물을지, 무엇을 실행할지, 잘못했을 때 무엇을 복구할지 함께 정한다.
입력 편의가 사용자의 의도나 실행 범위를 대신 결정하게 하지 않는다.

## 권한과 작업 모드

- 설계 모드는 입력·명령 계약과 대안을 만든다. 실제 제출이나 외부 효과를 발생시키지 않는다.
- 리뷰 모드는 요구사항·화면·실행 결과를 구분하고 확인하지 않은 효과를 성공으로 판정하지 않는다.
- 구현 모드는 승인된 파일·기능 범위에서만 바꾸고 기존 정책을 보존한다.
- 실제 결제·전송·삭제·대량 변경은 테스트 목적이라도 별도 권한이 필요하다.
- 자동완성·기본값·예측 결과를 사용자의 동의나 명령 실행 허가로 간주하지 않는다.
- 비밀값은 결과·로그·스크린샷에 노출하지 않는다. 민감정보 수집 범위를 임의로 늘리지 않는다.

## 비적용 조건과 경계

연결된 스킬은 현재 카탈로그에서 이름으로 찾아 읽는다. 없으면 해당 검토를 수행했다고 보고하지 않는다.

- 다단계 화면 자체가 필요한지는 정보 구조(`interface-architecture`)에서 결정한다.
- 폼의 배치·시각적 위계는 화면 배치(`interface-layout`)가 소유한다.
- 여러 개체의 선택 집합은 컬렉션 설계(`collection-data-design`)에서 받아 사용한다.
- 서버 검증·취소·인가·트랜잭션이 실제로 보장되는지는 관련 코드 검토가 소유한다.
- 보안 정책 수립, 비밀번호 길이 규칙 제정, 접근성 인증의 대체 절차가 아니다.

## 최소 입력

- 사용자 목표, 각 필드의 필요성·필수 여부·의미와 현재 제품 정책.
- 허용값·표시 형식·저장 형식·단위·지역별 차이·민감도.
- 명령의 대상·범위·예상 결과·외부 부작용·소요 시간·복구 가능성.
- 현재 폼·명령 UI, 실제 입력 예시, 오류 응답과 알려진 취소·undo 계약.
- 권한과 복구 보장을 알 수 없으면 확인된 범위만 설계하고 불가능한 안전성을 약속하지 않는다.
- 입력 예시가 없으면 가정한 변형을 명시한다. 사용자의 실제 데이터로 위장하지 않는다.

## 1. 질문과 입력 방식을 줄인다

1. 각 필드가 목표 달성에 필요한지 확인하고 사용하지 않는 수집은 제거 후보로 남긴다.
2. 이미 알고 있는 값은 재사용 가능성과 최신성을 확인한다. 추정값은 사용자 확인 없이 확정하지 않는다.
3. 필수·선택과 이유를 표현하고 선택 입력 때문에 필수 과업 완료를 막지 않는다.
4. 사용자가 제공할 수 없는 값을 내부 시스템의 필요 때문에 그대로 요구하지 않는다.
5. 형식 제한은 파서의 편의가 아니라 데이터 의미와 오류 비용으로 결정한다.

| 입력 특성 | 우선 방식 | 안전장치 |
|---|---|---|
| 뜻은 같고 표기만 다양 | 관대한 입력과 정규화 | 모호한 해석은 확정 전 되돌려 표시 |
| 구조가 안정적이고 사용자도 알고 있음 | 구조화 입력 | 붙여넣기·전체 수정·지역별 예외 허용 |
| 유한하고 익숙한 선택지 | 직접 선택 또는 검색 가능한 선택 | 항목 수·구별 단서·키보드 접근 고려 |
| 날짜·색 등 시각적 선택이 유리 | 복합 선택기 | 정밀 입력·현재값·확정·취소 경로 제공 |
| 여러 항목을 집합으로 구성 | 원본과 선택 집합의 구분 | 추가·제거·순서·중복 규칙 명시 |

- 전화·주소·이름을 한 국가의 고정 구조로 강제하지 않는다.
- 날짜와 단위가 모호하면 조용히 추정하지 말고 해석을 확인하거나 명확한 선택을 제공한다.
- 문장 중간에 입력을 넣으면 번역 어순과 조사의 변화를 확인한다.
- 입력칸 자동 이동은 연속 타이핑·붙여넣기·수정에 이익이 확인된 경우만 선택한다.

## 2. 라벨·힌트·기본값을 분리한다

- 라벨은 입력 중에도 필드의 정체성을 유지하게 한다.
- 힌트는 허용 형식·이유·제약을 설명하고 필요한 순간에 다시 볼 수 있게 한다.
- placeholder는 예시이지 값이나 유일한 라벨이 아니다.
- 기본값은 맞을 가능성과 틀렸을 때의 비용을 비교해 정한다.
- 민감한 동의나 정체성을 대신 선택하지 않는다. 정책상 허용된 기본값도 수정 가능성을 확인한다.
- 과거 입력을 재사용하면 대상·기간이 바뀌어 부적절한 값이 되었는지 확인한다.
- 비활성 필드는 왜 수정할 수 없는지와 어디서 바꿀 수 있는지 필요한 경우 설명한다.

## 3. 자동완성과 입력 이벤트의 의미를 정한다

- 추천은 사용자가 거절하고 원래 입력을 계속할 수 있어야 한다.
- 선택지로 제한된 필드와 자유 문자열에 추천만 제공하는 필드를 구별한다.
- 추천 항목 선택과 폼 제출에 같은 Enter가 충돌하지 않게 한다.
- 늦게 도착한 추천이 새 입력을 덮거나 다른 필드에 적용되지 않게 기대 동작을 정의한다.
- 붙여넣기·IME 조합·키보드 이동·모바일 키보드·저장된 자동완성을 관련 조건에서 확인한다.
- 계정·결제 등 전문 입력은 적합한 플랫폼·제공자 기능을 우선 검토한다.
- 실제 보안 규칙을 모르면 임의 비밀번호 점수나 형식 규칙을 만들지 않는다.

## 4. 검증 시점과 오류 복구를 정한다

- 입력 중에는 아직 완성되지 않은 값을 즉시 오류로 몰아붙이지 않는다.
- 명확한 길이 제한·금지값처럼 즉시 도움 되는 조건은 입력 중 안내를 비교한다.
- 필드를 떠난 뒤 판단할 수 있는 조건은 완료 기회를 준 후 검증한다.
- 서버·다른 필드에 의존하는 검증은 그 의존성과 대기 상태를 드러낸다.
- 오류는 해당 필드와 연결하고 원인·수정 방법을 구체적으로 적는다.
- 여러 오류가 있는 긴 폼은 요약에서 해당 필드로 이동할 수 있게 한다.
- 비활성 제출 버튼만으로 원인을 전달하지 않는다. 충족하지 못한 조건을 찾을 수 있어야 한다.
- 실패·중단 후 작성값을 보존하되 민감값의 보존은 명시된 보안 정책을 따른다.
- 클라이언트 통과가 서버 수락을 보장하지 않음을 고려하고 서버 오류를 복구 가능한 안내로 연결한다.

## 5. 명령의 발견성과 범위를 정한다

1. 명령마다 대상·개수·적용 범위·확정 시점·예상 효과를 기록한다.
2. 자주 쓰거나 필수인 명령은 눈에 보이는 경로에 둔다.
3. 반복 항목의 보조 명령은 문맥 도구로 줄일 수 있지만 hover만을 유일 경로로 삼지 않는다.
4. 같은 대상·범위의 명령을 묶고 항목 단위와 전체 단위 작업을 구별한다.
5. 현재 개체나 undo 대상처럼 결과 예측에 필요한 정보를 라벨에 넣는다.
6. 주요 완료 행동은 실제 커밋과 연결한다. 저장 없이 이동하는 행동을 저장처럼 표시하지 않는다.
7. 명령이 비활성화되면 선행조건과 해결 경로를 필요한 위치에 표시한다.

## 6. 미리보기·확인·실행 피드백을 선택한다

- 결과를 예측하기 어렵거나 수정 비용이 크면 커밋 전 미리보기를 우선 검토한다.
- 미리보기의 대상·금액·범위가 실행 시점과 달라질 수 있으면 재계산·재확인 조건을 정한다.
- 모든 행동에 반복 확인창을 붙이지 않는다. 실제 위험·복구 불가·범위 오해를 줄이는 경우에 사용한다.
- 되돌릴 수 있는 저위험 작업은 가벼운 실행과 명확한 undo가 더 적합한지 비교한다.
- 접수·처리 중·성공·실패·결과 미확정을 구분하고 성공을 접수 응답만으로 단정하지 않는다.
- 측정 가능한 완료량이 있을 때 진행률을 사용하고 없으면 진행 중 신호와 필요한 설명을 제공한다.
- 완료 시간 추정이 없으면 임의 수치로 채우지 않는다.
- 중복 실행 위험이 있으면 재입력 정책을 정하고 결과 미확정에서 무조건 재시도를 유도하지 않는다.

## 7. 취소·되돌리기·이력을 구분한다

| 행동 | 의미 | 반드시 정할 경계 |
|---|---|---|
| 닫기 | 현재 표시를 떠남 | 작업 지속 여부·초안 보존·복귀 경로 |
| 취소 요청 | 진행 중 작업의 중단을 요구 | 중단 확정 시점·이미 발생한 효과·실패 가능성 |
| undo | 완료된 변경을 역전 | 작업 단위·대상·수명·역전 가능한 상태 |
| 보상 조치 | 원래 효과를 지우지 못한 채 후속 처리 | 남는 기록·추가 비용·승인과 실패 |
| 이력 | 수행한 일을 설명 | 대상·시각·결과와 재실행 가능 여부 |

- 네트워크 요청 중단이나 창 닫기를 서버 효과 취소로 표현하지 않는다.
- undo 단위는 사용자 의미에 맞춘다. 글자 하나·필드·한 번의 명령 중 무엇인지 정한다.
- 다음 undo가 어떤 개체의 어떤 작업인지 실행 전에 알 수 있게 한다.
- 새 작업 후 redo, 문서 전환, 새로고침, 외부 편집으로 복구 범위가 바뀌는 조건을 정한다.
- 다른 사용자의 변경을 무조건 덮어쓰는 undo를 안전한 기본값으로 삼지 않는다.
- 이력에 보인다는 이유만으로 되돌리기나 재실행을 허용하지 않는다.
- 반복 작업 묶음은 실제 반복 필요가 있을 때만 제공하고 대상·권한·부분 실패를 드러낸다.
- 재실행 전 이전 입력과 현재 대상이 여전히 유효한지 확인할 조건을 정한다.

## 실패모드와 수정 방향

- 자동완성이 원래 의도를 덮음: 추천과 확정값을 분리하고 거절·수정 경로를 보존한다.
- 지역 형식을 오해석해 잘못 저장: 정규화 결과를 드러내고 모호한 입력을 확인한다.
- 비활성 버튼뿐이라 완료 불가: 충족할 조건과 해당 필드로의 경로를 제공한다.
- 미리보기와 실제 범위가 다름: 실행 직전 대상·버전 확인 계약을 정한다.
- 취소 UI만 닫히고 작업은 실행됨: 닫기와 중단 요청·결과를 구별한다.
- undo가 다른 문서나 타인의 작업을 덮음: 대상과 복구 범위를 제한하고 충돌을 표시한다.

## 검증

1. 허용 형식·지역 변형·모호한 값·붙여넣기·추천 거절을 관련 필드에서 확인한다.
2. 입력 도중 이탈·복귀, 오류 수정, 재제출 시 값과 명령 대상이 유지되는지 확인한다.
3. 명령의 접수·진행·완료·미확정에서 문구와 실제 효과의 구분을 확인한다.
4. 취소가 수락되기 전후, 완료 후 undo, 외부 변경 후 undo의 기대 결과를 비교한다.
5. 상태 일치는 상태 검토(`ux-state-review`)에 필요한 전환만 인계한다.
6. 실제 실행은 허용된 테스트 환경에서 브라우저 검증(`browser-e2e-review`)을 연결한다.
7. 미리보기만 구현했다면 서버 효과·취소·undo까지 검증했다고 보고하지 않는다.

## 결과

- 필드별 필요성·허용값·표시/저장 의미·힌트·기본값·검증 시점.
- 명령별 대상·범위·확정·피드백과 취소·undo·비가역 경계.
- 선택한 방식과 대안, 정책 의존성, 확인이 필요한 서버 보장.
- 실패모드별 확인 조건, 실제 증거, 미검증 영역.
- 중요한 정책·시안 인계가 있을 때만 결정 보존(`preserve-decisions`)에 기존 결정을 연결한다.
