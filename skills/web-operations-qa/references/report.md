# 증거와 결과 보고

요청 규모에 맞게 아래 내용을 통합하되, 근거·원인 가설·실제 조치·검증·운영 적용을 구분한다. 소규모 조사에 빈 섹션을 늘리지 않는다.

1. **핵심 결론**: 먼저 처리할 문제와 이유, 지금 유지할 항목.
2. **운영 범위와 기준선**: 리소스·기간·트래픽·지연·오류·저장량·비용 중 조사한 항목. 수치별 정의·출처·조건·표본·한계.
3. **발견 요약**: ID / 문제 / 사용자·데이터 영향 / 근거 / 확신 / 우선순위 / 최소 개선 / 검증 방법 / 상태.
4. **발견 상세**: 관측 위치·재현/재조회 방법, 영향받는 여정·요청·작업, 확인 사실과 원인 가설, 대안 원인의 검토/배제 근거, 최소 변경·부작용, 성공 기준, 적용·중단·복구 절차.
5. **실제 변경과 테스트**: 파일·설정·diff·실행 결과, 실패하거나 수행하지 못한 검증. 계측만 추가한 경우 병목 해결과 구분.
6. **전후 비교**: 같은 조건의 측정값·표본·변동. 예상 효과와 실제 결과, 로컬/격리 환경 결과와 운영 결과를 분리.
7. **미확인·후속 조치**: 필요한 권한·계측·적용 승인·추가 관측을 구체화.
8. **증거 목록**: 문제 ID별 유효한 HAR/대체 네트워크 기록·캡처·trace·헤더·지표 조회·설정/코드 위치·테스트 결과.

다음 상태를 필요한 만큼 조합해 표시한다. 단일 진행 단계로 사실의 확신과 적용 여부를 혼동하지 않는다.

- 사실/원인: `확인됨 / 가설 / 계측 필요`.
- 구현/검증: `수정 구현됨 / 테스트 통과`.
- 운영/효과: `운영 적용 대기 / 운영 적용됨 / 효과 검증됨`.
- 범위/제약: `차단 / 미확인 / 해당 없음`.

예: `원인 확인됨 · 수정 구현됨 · 테스트 통과 · 운영 적용 대기`는 운영 성능 개선 완료가 아니다. `운영 적용됨 · 효과 관측 필요`도 효과 검증과 다르다. 보고서만으로 담당자가 변경 이유·적용 증거·중단과 복구 방법을 판단할 수 있게 한다.
