# Reader and evidence gates

각 항목에 대해 단순한 합계 점수 대신 통과/수정 필요/검증 불가와 근거를 기록한다. 승인된 문서형 화면을 다른 형식으로 대체하는 것은 가독성 수정과 별개 결정이다.

## 읽기 순서 검수

위에서 아래로 실제 화면을 읽으면서 확인한다.

| 시점 | 독자가 지금 답할 수 있어야 하는 것 | 실패 예 |
| --- | --- | --- |
| 제목·상황 | 누가 무엇을 하다 무슨 결과를 겪는가? 확정인가? | 코드 함수명만 있는 제목, 후보를 확정 결함처럼 표현 |
| 기대 동작 | 원래 무엇이 보장되어야 하는가? | 정상 계약 없이 위험만 나열 |
| 대상과 역할 | 각 데이터는 어디에 있고 원본/사본 중 무엇인가? | “캐시”, “상태”, “서버”를 소유자 없이 사용 |
| 전후 단계 | 어떤 조건과 순서가 결과를 만들며 무엇이 바뀌는가? | 연속 호출과 대안 경로 혼동, 원인 없이 해결책만 제시 |
| UML 진입 | 그림에서 어느 이름·화살표를 따라가야 하는가? | 범례·이름 대응표가 그림보다 뒤에만 있음 |
| 검증·근거 | 무엇이 입증됐고 무엇이 제안/미확인인가? | 정적 코드 추적을 운영 재현·배포로 표현 |

정보가 부족하면 형용사를 늘리지 말고 빠진 관계를 채운다. 위치, 소유자, 읽기/쓰기 주체, 사본의 수명, 실행 조건 중 독자가 추론해야 하는 것을 찾는다. 내용이 과밀하면 결론을 지우지 말고 상세 코드/수명/근거를 두 번째 층으로 옮긴다.

## 의미 검수

- 실제 식별자와 고정 소스 위치가 연결된다. 클래스/함수의 소유자, 컬렉션/메모리 속성 차이가 맞다.
- 그림, 쉬운 설명, 다운받는 정의가 같은 사실과 조건을 표현한다.
- 현재 구현에 없는 이름과 경로는 제안으로 표시한다. 예시 객체·값은 실제 운영 데이터처럼 쓰지 않는다.
- 그래프의 모든 연결은 근거가 있다. 객체/컴포넌트 화살표를 시간 순서로 읽게 만들지 않는다.
- 조건부 위험에는 성립 조건과 확인 방법이 있다. 제외 항목에는 제외 근거와 미확인 범위를 남긴다.

## 화면 및 동작 검수

- 예시 뷰포트: 1440×900과 390×844. 실제 요청 기기가 있으면 우선한다. 크기는 인증 기준이 아니다.
- 모든 항목과 전후 SVG가 존재하고 비어 있지 않다. SVG XML과 포함된 JavaScript를 검사한다.
- 페이지 전체의 의도하지 않은 가로 넘침, 글자 잘림, 노드/라벨 겹침을 확인한다. 긴 식별자를 중간에서 잘라 이름을 훼손하거나 그림 전체를 축소해 해결하지 않는다.
- 보통 본문은 15–17px부터 시작하고 기술 그림도 실제 화면에서 판독 가능한 크기로 조정한다. 고정 수치를 통과했다는 이유만으로 가독성을 승인하지 않는다.
- 기본 기술 영역은 접혀 있고, 펼치면 이름 대응표가 그림보다 먼저 나온다. 이전 크게/이후 크게/전후 함께/확대와 닫기를 확인한다.
- 검색은 쉬운 제목과 실제 코드 이름으로 동작한다. 빈 검색 결과, 판정 필터, UML 필터, 해시 링크, 이전/다음 항목을 확인한다.
- 키보드 포커스, 모바일 목록 열기/닫기, 그림의 국소 스크롤, 큰 글씨 단계 설명을 확인한다.
- SVG/정의 다운로드를 제공하면 현재 선택한 항목과 전후 방향, 유형이 맞는지 실제 결과를 확인한다.

## 남길 기록

기준 소스, 산출물 해시, 항목/그림 수, 검사 범위, 실제 뷰포트, 스크린샷, 동작 재현, 실패와 복구, 검증하지 않은 범위를 남긴다. 같은 출처 iframe은 물리 기기 테스트가 아니다. 자동 레이아웃 측정은 의미 정확성이나 인간의 이해도를 입증하지 않는다. 공개 호스팅·제품 배포를 하지 않았다면 로컬 미리보기라고 전달한다.
