# UI text patterns

패턴은 시작점이다. 실제 동작과 사용자 언어가 우선이며 영어의 어순·단어 수를 모든 언어에 고정하지 않는다.
각 요소는 주변 제목·설명·선택지와 함께 작성하고 접근 가능한 이름까지 전달한다.

## 제목

- 여러 목적의 화면은 영역이나 콘텐츠 이름으로 맥락을 설정한다.
- 한 가지 과업의 화면은 사용자가 할 일을 명명한다.
- 진입점과 도착 화면에서 개념을 바꾸지 않는다. 이름을 바꿨다면 연결 콘텐츠도 갱신한다.
- 브랜드 이름 반복은 실제 식별 목적이 있을 때만 쓴다.

## 버튼과 메뉴

- 행동은 구체적인 동사와 필요하면 대상을 쓴다. 예: `예약 변경`, `초대 보내기`.
- 마지막 확정에는 실제 약속을 드러낸다. `계속` 뒤에서 비용 청구·외부 게시가 일어나게 하지 않는다.
- 탐색 메뉴는 도착 영역의 이름도 가능하다. 같은 집합에서 겹치는 뜻과 길이 차이를 비교한다.
- 아이콘 버튼은 화면 밖에서도 대상과 행동이 구별되는 이름을 제공한다.
- 예: 반복된 `삭제` 대신 접근 가능한 이름에 해당 파일의 이름을 포함한다.

## 설명과 안내

- 어떤 결과를 얻으려면 무엇을 해야 하는지, 어떤 조건이면 무슨 일이 일어나는지 설명한다.
- 사용자가 행동할 순서대로 지시한다. 위치에 간 뒤 조작한다면 위치를 먼저 알려준다.
- 핵심 조건·가격·취소 불가·데이터 이용은 결정 전에 보이게 한다.
- 선택적인 상세 도움은 별도 경로로 제공하되 핵심 위험을 그곳에만 숨기지 않는다.
- 링크는 이동 목적을 담은 구절을 연결한다. `여기`만 읽혀서는 목적을 알 수 없다.
- 법적 요구의 정확성과 읽기 쉬움을 함께 협의한다. 짧게 만들기 위해 의무 고지를 임의로 삭제하지 않는다.

## 빈 상태

- 데이터가 없는 이유와 정상 상태인지 확인한다. 조회 실패·권한 없음·미확인을 빈 결과로 포장하지 않는다.
- 첫 사용이면 앞으로 들어올 내용과 시작 방법을 안내한다.
- 검색 결과 없음이면 검색 조건 수정이나 초기화 등 실제 가능한 행동을 제시한다.
- 다른 사람의 행동을 기다리는 상태라면 무엇이 일어났을 때 채워지는지 설명한다.
- 사용자가 채울 수 없는 영역에 무의미한 생성 버튼을 두지 않는다.
- 예: `등록된 기기가 없습니다. 기기를 연결하면 사용 기록을 볼 수 있습니다.`와 `기기 연결`.

## 라벨과 데이터

- 항목의 뜻과 단위를 명명한다. 표의 헤더, 값, 날짜·통화 표기를 한 세트로 설계한다.
- 날짜는 시간대와 기준 시점, 금액은 통화와 부호, 수치는 단위·반올림·규모를 정한다.
- `0`, 값 없음, 아직 확인 중, 제공하지 않음을 구분한다.
- 짧은 전치사나 생략형에 과도한 의미를 맡기지 않는다. 다른 언어의 어순과 더 긴 표현도 수용한다.

## 컨트롤

- 이름과 현재 상태가 합쳐져 뜻이 통하는지 확인한다.
- 체크됨·체크 안 됨 또는 켜짐·꺼짐에서 같은 라벨의 의미가 뒤집히거나 이중 부정이 되지 않게 한다.
- 관련 설정은 공통 제목과 병렬 표현으로 묶되 지원 안내에서 각 설정을 가리킬 수 있어야 한다.
- 슬라이더는 범위·단위·양끝 의미를, 선택 컨트롤은 선택 결과를 표현한다.

## 입력 필드

- 필드 이름은 입력 뒤에도 남긴다. 예시·힌트는 라벨과 다른 정보를 보완한다.
- 형식이나 제약은 오류 후가 아니라 입력할 때 필요한 위치에 제공한다.
- 필수·선택, 정보 수집 이유와 민감성은 정책에 맞게 설명한다.
- 기본값은 알고 있는 사실일 때만 채우며 수정할 수 있게 한다. 추측과 예시는 실제 값처럼 넣지 않는다.
- AI가 채운 초안은 검토할 내용임을 드러내고 정확성 확인 경로를 제공한다.

## 진행과 완료

- 진행은 실제 처리 중인 행동과 대상을 표시한다. 완료 전에 성공으로 말하지 않는다.
- 남은 시간과 진행률은 근거가 있을 때만 제공한다. 알 수 없으면 확정적 약속을 피한다.
- 완료는 끝난 단위를 명시한다. `요청 접수`와 `승인 완료`, `임시 저장`과 `게시 완료`는 다르다.
- 후속 처리가 남으면 처리 주체, 필요한 사용자 행동과 알려진 예상 시점을 설명한다.
- 변화 자체가 충분히 명확하면 중복 확인을 줄이되 비시각 사용자에게도 전달되는지 확인한다.

## 알림

- 누가 왜 지금 받아야 하는지, 얻게 되는 가치, 처음 할 행동을 정한다.
- 잠금 화면·배너·알림 센터에서 잘린 제목만 보여도 핵심 의미가 남게 한다.
- 민감한 메시지 본문과 계정·건강·금융 정보를 불필요하게 노출하지 않는다.
- 같은 사람이 받을 전체 빈도와 시간, 중복 억제와 구독 설정을 함께 검토한다.
- 알림을 열어도 해당 일을 완료할 수 없다면 목적과 연결 경로를 다시 설계한다.

## 오류

- 인라인 수정: 해당 필드와 필요한 수정 조건을 연결한다. 예: `날짜를 시작일 이후로 선택하세요`.
- 우회 가능: 원래 목표에 도달하는 다른 행동을 가장 두드러지게 제시한다.
- 진행 불가: 막힌 이유와 다시 가능해지는 조건을 확인된 범위에서 설명한다.
- 시스템이 모르는 원인을 단정하거나 사용자 잘못으로 돌리지 않는다.
- `다시 시도`는 같은 요청을 반복해 해결될 수 있을 때만 제시한다.
- 입력 보존 여부, 중복 실행 위험, 지원 문의에 필요한 식별 정보도 함께 검토한다.
- 기술 세부 사항은 복구나 업무상 책임 확인에 도움이 될 때 단계적으로 제공한다.
- 사과는 실제 불편·손실과 브랜드 맥락에 맞춰 쓴다. 사과만 있고 해결 정보가 없는 오류는 완성되지 않았다.
