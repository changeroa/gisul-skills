# 시나리오 추적과 반례 검토

## 추적 표

각 행은 하나의 의미 있는 이벤트와 그 효과를 연결한다.

```text
시나리오 / 시작 상태 / 직접 입력 주체 / 시스템 이벤트·입력
적용 연산 계약 / 생성·변경·해제되는 객체·링크
유지할 불변식 / 기대 출력·외부 효과 / 관찰 지점·증거
판정: 모델 검토·소스 추적·실행 확인·미검증
```

시나리오의 한 단계가 반드시 하나의 연산과 대응하지는 않는다.
한 연산이 여러 시나리오에서 공유되면 각 시나리오의 조건 차이를 보존한다.
개념·연관·속성에 근거 없는 항목이 있으면 현재 범위에서 필요한 이유를 다시 묻는다.

## SSD 검토

- 한 시나리오의 직접 외부 주체와 시스템 경계가 명확한가?
- 입력 이름이 장치나 UI가 아니라 의도 수준의 행위를 표현하는가?
- 매개변수와 출력의 의미가 용어집·계약과 일치하는가?
- 이벤트 순서와 반복·대안 조건이 시나리오 본문에 근거하는가?
- 외부 시스템은 블랙박스로 남아 있는가?
- 내부 설계 호출이 경계 이벤트처럼 섞이지 않았는가?
- 타이머·장애·다른 시스템이 만드는 사건을 필요한 범위에서 포함했는가?

## 반례 선택

모든 조합을 생성하지 말고 규칙을 깨뜨릴 수 있는 최소 사례를 고른다.

| 관점 | 최소 반례 후보 |
|---|---|
| 정체성 | 값이 같은 별개 대상, 다른 계정의 동일 식별자 |
| 연관 | 객체는 생겼으나 연결되지 않음, 다른 대상에 연결됨 |
| 다중성 | 0개·1개·상한 직전·상한 초과, 초기 상태와 완료 상태 차이 |
| 역할 | 한 대상의 동시 역할, 역할 종료 뒤 권한·이력의 잔존 |
| 시간 | 유효기간 시작·끝, 겹침·공백, 현재 값 수정 뒤 과거 조회 |
| 단위 | 숫자는 같지만 다른 통화·단위, 변환·반올림 경계 |
| 상태 | 전제 위반, 순서 역전, 종료 뒤 재진입 |
| 외부 효과 | 요청 수락 뒤 실패, 응답 유실, 중복·지연·부분 완료 |

기능에 없는 보존·복구·중복 방지 요구를 임의로 추가하지 않는다.
모호한 정책은 결함 확정이 아니라 결정이 필요한 사항으로 남긴다.

## 판정 근거

초기 상태와 입력을 고정하고 기대 결과를 계약에서 독립적으로 도출한다.
구현의 계산식을 다시 실행해 같은 값을 얻는 방식은 독립 oracle이 아니다.
내부 호출 순서보다 의미 있는 최종 상태·경계 메시지·저장 결과를 관찰한다.
중간 상태가 계약에 중요하면 그 관찰 지점도 포함한다.
대역을 사용하면 대역 바깥의 실제 효과까지 확인했다고 쓰지 않는다.
실행하지 않은 사례는 검토·제안으로 표시한다.

## 유스케이스 관계

먼저 목표, 주요 흐름과 대안·실패 결과를 본문으로 작성한다.
공유되는 하위 흐름이나 지나치게 긴 본문을 분리하면 이해가 개선될 때 include를 고려한다.
include는 기본 흐름에서 포함 흐름을 가리킨다. 분기 안의 포함은 모든 실행 경로에 무조건 발생한다는 뜻이 아니다.
단순 선택 동작은 본문의 대안 흐름으로도 충분하다.
extend를 쓰면 기본 흐름 자체가 완결돼야 하며 확장 지점과 발동 조건을 정한다.
extend는 확장 흐름에서 기본 흐름을 가리킨다.
관계의 종류를 고르는 토론이 업무 의미·실패 결과·입출력의 명세를 지연시키지 않게 한다.

## 변경 후 갱신

구현·테스트·사용자 피드백이 기존 가정을 깨뜨리면 영향받는 용어·관계·이벤트·계약을 추적한다.
변경을 모델 전체 재작성으로 확대하지 말고 관련 범위에서 교정한다.
모델의 소비자와 유지 목적이 없으면 폐기·보관을 선택할 수 있다.
오래된 모델을 최신 명세처럼 제시하지 않는다.
