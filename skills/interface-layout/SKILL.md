# 화면 배치와 반응형 구성

정보의 중요도와 관계를 배치로 표현한다.
여백이나 화면의 단순함 자체를 목표로 삼지 않는다.

## 권한과 작업 모드

- 설계 모드에서는 배치 대안과 적용 조건을 제안한다.
- 리뷰 모드에서는 실제 보이는 문제와 예상 위험을 구분한다.
- 구현 모드에서는 요청된 스타일·컴포넌트 범위만 바꾸고 유지할 기능을 보존한다.
- 화면 정돈 요청은 기능 삭제, 필수 단계 변경, 데이터 수집 정책 변경을 허용하지 않는다.
- 외부 게시·배포·사용자 설정 초기화는 이 스킬의 기본 권한에 포함되지 않는다.

## 비적용 조건과 경계

연결된 스킬은 현재 카탈로그에서 이름으로 찾아 읽는다. 없으면 해당 검토를 수행했다고 보고하지 않는다.

- 개체 분류·화면 임무·경로가 미정이면 정보 구조(`interface-architecture`)를 먼저 정한다.
- 차트의 축·인코딩·데이터 비교는 컬렉션과 데이터(`collection-data-design`)가 소유한다.
- 폼 검증과 명령의 실행 의미는 입력과 명령(`form-command-design`)으로 넘긴다.
- 일반적인 발견 가능성 평가는 사용성 리뷰(`dont-make-me-think`)에 필요한 부분만 연결한다.
- 브랜드 전략, 일러스트 제작, 접근성 인증 전체를 수행하는 절차가 아니다.

## 최소 입력

- 화면의 주 임무와 사용자가 가장 먼저 판단하거나 실행할 것.
- 콘텐츠 관계, 동시에 비교해야 할 항목, 유지해야 할 행동과 상태.
- 실제 시안·렌더링, 기존 컴포넌트·스타일 기준, 변경 가능한 범위.
- 대상 화면 폭, 입력 방식, 언어, 긴 문구·빈 내용·오류·로딩의 예시.
- 실제 렌더링이 없으면 구성 제안으로 한정하고 시각 검증 완료로 표현하지 않는다.
- 빠진 기기 조건은 대표 가정을 명시해 진행하되 전 기기 지원을 주장하지 않는다.

## 1. 위계를 먼저 정한다

1. 주 작업 영역, 핵심 상태, 주요 행동, 보조 정보, 부차적 탐색을 구별한다.
2. 사용 빈도와 오류 비용을 함께 고려한다. 드물어도 위험한 상태는 눈에 띄어야 한다.
3. 크기·위치·대비·여백 중 어떤 수단이 각각의 우선순위를 표현할지 정한다.
4. 모든 요소를 강조하지 않는다. 같은 강조는 같은 중요도를 뜻하는지 확인한다.
5. 부차적 장식을 제거하되 사용자가 비교하는 정보와 조작 단서는 남긴다.
6. 첫 인상만 아니라 내용을 읽고 행동까지 이어지는 시선 흐름을 확인한다.

## 2. 의미와 그룹화를 일치시킨다

- 관련 항목 사이의 거리를 다른 그룹과의 거리보다 작게 두어 관계를 드러낸다.
- 제목·테두리·배경을 중첩하기 전에 간격과 정렬만으로 그룹이 구별되는지 본다.
- 같은 형태가 같은 의미를 암시한다면 서로 다른 역할을 구분할 다른 단서도 둔다.
- 라벨과 값, 값과 단위, 설명과 해당 필드는 가까이 둔다.
- 화면을 채우려고 간격을 늘려 의미상 연결을 끊지 않는다.
- 표의 열 비교가 중요하면 숫자·단위·소수점의 읽기 기준을 맞춘다.
- 읽기 방향과 번역 길이를 고려하고 한 언어의 줄바꿈에만 맞춰 정렬하지 않는다.

## 3. 배치 구조를 선택한다

| 요구 | 우선 선택 | 선택을 바꿀 조건 |
|---|---|---|
| 하나의 콘텐츠를 오래 읽거나 편집 | 중심 작업 영역과 보조 도구 | 여러 항목의 동시 비교가 핵심이면 분할 구성 |
| 동등한 항목을 빠르게 훑기 | 반복 그리드와 일관된 정보 순서 | 정확한 열 비교가 핵심이면 표 형태 검토 |
| 독립된 내용 묶음을 구별 | 제목 있는 섹션 | 화면 길이가 과업을 방해하면 선택적 접기 |
| 한 번에 한 내용 묶음만 필요 | 탭 | 서로 참조해야 하면 동시 노출 또는 분할 |
| 순서 있는 내용을 여러 곳 펼쳐 참조 | 아코디언 | 전체 개관이 더 중요하면 펼친 섹션 유지 |
| 주 과업 옆에 선택적으로 필요한 도구 | 접이식 보조 패널 | 필수 행동을 숨기게 되면 고정 노출 |
| 역할마다 모듈 우선순위가 크게 다름 | 이동·숨김 가능한 패널 | 사용자 설정 비용이 이익보다 크면 고정 배치 |

- 탭·패널 수를 고정 숫자로 정하지 않는다. 라벨 길이·비교 요구·발견 비용으로 선택한다.
- 아코디언은 여러 항목을 열어야 하는지 먼저 정하고 무조건 하나만 열리게 하지 않는다.
- 숨김과 비활성화를 구분한다. 선행조건을 배워야 하면 존재와 조건을 드러낸다.
- 선택적 고급 기능이면 점진 공개를 쓰되 현재 적용 중인 값은 숨기지 않는다.
- 맞춤 배치에는 쓸 만한 초기값, 숨긴 패널 재추가, 기본 배치 복원을 제공한다.

## 4. 그리드와 반응형 전환을 정한다

1. 콘텐츠가 읽히고 조작 가능한 최소 폭에서 시작해 열의 필요 폭을 계산한다.
2. 기기 이름이 아니라 라벨 충돌·콘텐츠 압축·비교 불가가 생기는 지점을 전환점으로 삼는다.
3. 폭이 줄면 주변 여백, 열 수, 배치, 보조 영역 노출을 순서에 맞게 재검토한다.
4. 좁은 화면의 단일 열은 읽기·행동 순서를 보존하도록 쌓는다.
5. 가로 비교 자체가 과업이면 억지로 카드로 바꾸지 말고 가로 탐색과 행·열 식별을 검토한다.
6. 긴 코드·표·이미지처럼 예외적인 콘텐츠의 넘침 정책을 별도로 정한다.
7. 확대와 번역에서도 의미·주요 행동이 사라지지 않게 한다.
8. CSS 시각 순서를 바꿨다면 DOM 읽기·포커스 순서와 충돌하는지 확인한다.
9. 데스크톱의 주요 기능을 모바일에서 삭제하지 말고 다른 진입 경로나 배치를 제공한다.

## 5. 가독성과 조작 공간을 맞춘다

- 글자 크기를 고정된 수치에 맞추지 말고 사용 환경·실제 글꼴·확대로 검증한다.
- 금액·코드·식별자는 0/O, 1/l처럼 혼동하기 쉬운 문자를 실데이터로 비교한다.
- 행 길이·행간·대비를 조정할 때 읽기 속도뿐 아니라 정보 비교의 밀도를 보존한다.
- 같은 중요도·상태를 색만으로 구분하지 않는다. 라벨·형태·위치 등 다른 단서를 둔다.
- 터치 영역과 인접 간격은 현재 플랫폼 기준과 실제 입력 방식을 함께 확인한다.
- 아이콘의 문화적 의미를 보편적이라고 가정하지 않는다. 불명확하면 텍스트를 병기한다.
- 사용자 테마·고대비·텍스트 확대가 적용되어도 내용과 조작 단서를 유지한다.

## 6. 변화하는 화면과 재사용을 다룬다

- 이미지·로딩·오류가 나중에 나타날 공간이 예측 가능하면 필요한 자리를 예약한다.
- hover 도구가 생겨도 항목과 클릭 대상이 밀리지 않도록 한다.
- 고정 헤더·하단 행동 영역은 콘텐츠·포커스·화면 키보드와 겹치는지 확인한다.
- 애니메이션은 상태 사이의 관계를 설명할 때 사용하고 반복 입력을 대기열에 가두지 않는다.
- 모션 감소 환경에서도 전환 결과를 이해할 수 있어야 한다.
- 공통 간격·타입·색을 기존 토큰에 연결하고 같은 의미의 컴포넌트 변형을 줄인다.
- 같은 모양을 강제해 다른 의미를 숨기지 않는다. 예외는 사용자 과업 차이로 설명한다.
- 컴포넌트 단독 시안뿐 아니라 실제 콘텐츠를 넣은 전체 화면으로 조합을 확인한다.

## 실패모드와 수정 방향

- 빈 공간은 넓지만 관계를 읽기 어려움: 관련 항목 간 거리와 그룹 경계를 다시 정한다.
- 업무 정보가 모두 카드로 쪼개져 비교 불가: 비교 축을 공유하는 배치로 바꾼다.
- 깔끔한 탭이 기억 부담을 만듦: 필요한 묶음만 동시에 노출한다.
- 좁은 화면에서 주요 행동이 없어짐: 우선순위와 진입 경로를 보존하여 재배치한다.
- 긴 제목·오류에서 버튼이 이동하거나 가려짐: 콘텐츠 변형과 공간 정책을 보강한다.
- 모든 상태가 색만 다름: 텍스트나 비색상 단서로 의미를 중복 전달한다.
- 디자인 시스템과 일치하지만 실제 화면은 실패함: 조합 수준의 예외와 데이터 길이를 검증한다.

## 검증

1. 대표 화면에 정상·가장 긴 내용·최소 내용·오류를 넣어 위계와 조작 위치를 비교한다.
2. 넓은 폭과 좁은 폭뿐 아니라 레이아웃 전환점의 양쪽을 확인한다.
3. 텍스트 확대, 긴 번역, 키보드 포커스, 화면 키보드가 관련되면 해당 조건을 검사한다.
4. 비교 과업의 두 대상을 번갈아 기억하지 않고 읽을 수 있는지 확인한다.
5. 패널 숨김·복원, 도구 노출, 로딩 전후에서 주요 요소의 위치 변화를 확인한다.
6. 시각적 회귀를 실제 실행할 때만 브라우저 검증(`browser-e2e-review`)을 연결한다.
7. 스크린샷으로 알 수 없는 포커스·확대·입력 동작은 미검증으로 남긴다.

## 결과

- 화면 임무와 시각적 우선순위, 동시 노출이 필요한 정보.
- 선택한 그리드·탭·패널 구조와 기각한 대안의 비용.
- 콘텐츠 기반 전환 조건, 숨김·복원·넘침·고정 영역 규칙.
- 실제 콘텐츠로 확인한 조합, 수정 근거, 미검증 환경.
- 시안 버전과 유지할 기능은 필요할 때만 결정 보존(`preserve-decisions`)에 연결한다.
