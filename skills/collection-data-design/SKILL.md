# 컬렉션과 데이터 탐색 설계

찾기·비교·선택·이해 중 무엇이 주 과업인지 먼저 정한다.
목록과 시각화의 표현은 데이터 구조와 사용자의 질문에 맞춰 선택한다.

## 권한과 작업 모드

- 설계 모드는 표현 대안과 선택·필터의 의미 계약을 만든다.
- 리뷰 모드는 현재 표현과 사용자 과업의 불일치를 근거와 함께 보고한다.
- 구현 모드는 요청된 변경만 수행하며 기존 데이터 범위·권한·단위·집계 의미를 보존한다.
- 데이터를 볼 수 있다는 이유로 원본 다운로드·외부 전송·삭제·일괄 변경을 실행하지 않는다.
- 표나 차트가 정상 표시된 것만으로 수치 정확성, 전체 데이터 완전성, 인과관계를 확정하지 않는다.

## 비적용 조건과 경계

연결된 스킬은 현재 카탈로그에서 이름으로 찾아 읽는다. 없으면 해당 검토를 수행했다고 보고하지 않는다.

- 전역 분류·탐색과 화면 임무는 정보 구조(`interface-architecture`)가 소유한다.
- 공간 배분·반응형 배치는 화면 배치(`interface-layout`)에 인계한다.
- 선택한 항목에 명령을 실행할 때의 부작용·undo는 입력과 명령(`form-command-design`)이 소유한다.
- 계산·인가·동시성의 코드 정확성은 해당 전문 검토로 넘긴다.
- 장식용 그래픽 제작, 통계적 인과 추론, 분석 결론 작성의 대체 절차가 아니다.

## 최소 입력

- 사용자의 질문과 주 과업: 전체 파악, 특정 항목 찾기, 비교, 일괄 처리, 관계 탐색.
- 항목 수와 변동 폭, 안정적 식별자, 속성·단위·시간 범위·누락값의 의미.
- 정렬·그룹·계층, 항목별 정보량, 단일/다중 선택, 갱신·로딩 방식.
- 실제 예시와 현재 화면, 기기·입력 방식, 보존해야 할 필터·선택 계약.
- 데이터의 일부만 있으면 그 표본으로 가능한 검토만 수행하고 전체 분포를 추정하지 않는다.
- 선택 범위나 집계 의미가 미정이면 명시한 가정별 대안을 만들고 확정된 동작처럼 보고하지 않는다.

## 1. 컬렉션의 표현을 선택한다

| 주된 요구 | 우선 표현 | 피할 오용 |
|---|---|---|
| 여러 항목의 같은 속성을 정확히 비교 | 정렬 가능한 표·일관된 열 | 항목마다 다른 위치의 카드로 비교 축 분산 |
| 이미지로 대상을 식별 | 썸네일 그리드와 핵심 메타데이터 | 의미 있는 영역을 임의 crop으로 제거 |
| 항목별 풍부하고 서로 다른 설명 | 카드·목록과 상세 | 길이 차이가 중요도 차이처럼 보이게 배치 |
| 한 항목씩 연속 검토하며 목록 문맥 유지 | 분할 뷰 | 좁은 공간에서 양쪽 내용을 모두 압축 |
| 하나의 상세에 집중하고 공간이 부족 | 상세 화면 이동 | 목록 복귀·이전/다음·선택 위치를 잃음 |
| 여러 상세를 동시에 비교 | 인라인 펼침·비교 뷰 | 상세 하나를 열 때 다른 항목을 강제로 닫음 |

- 카드·표·그리드를 제품 전체의 단일 기본값으로 강제하지 않는다.
- carousel은 제한된 영역에서 우연한 발견이 목적일 때 비교한다.
- 특정 항목을 빠르게 찾거나 전체 항목을 검사해야 하면 직접 접근 가능한 목록을 우선한다.
- 가장 길고 짧은 항목, 이미지 없음, 긴 제목과 숫자로 표현 선택을 확인한다.

## 2. 로딩·정렬·위치 복원을 정한다

- 끝없는 탐색이 주 과업이면 점진 로딩을 검토하되 새 로딩 실패와 재시도를 구별한다.
- 위치 공유·특정 구간 접근·끝 확인이 중요하면 페이지 또는 명시적 구간 탐색을 우선한다.
- 정렬과 필터가 현재 로드한 항목만 대상으로 하는지 전체 결과 대상으로 하는지 밝힌다.
- 로컬 항목만 정렬하면서 전체 결과가 정렬된 것처럼 표시하지 않는다.
- 같은 정렬값을 가진 항목에도 안정적인 순서를 제공할 기준이 있는지 확인한다.
- 목록 복귀 시 필터·정렬·현재 항목·페이지·스크롤 중 무엇을 복원할지 정한다.
- 갱신으로 항목 위치가 바뀌면 사용자의 현재 작업을 밀어내지 않도록 갱신 표시나 적용 시점을 선택한다.
- 전체 개수가 알려지지 않았으면 정확한 총량이나 마지막 페이지를 만들어내지 않는다.

## 3. 선택의 집합과 수명을 정한다

1. 행 포커스, 현재 상세, 체크된 항목, 명령 대상 집합을 별개로 정의한다.
2. 선택은 화면상의 위치가 아니라 안정적 개체 식별자에 연결한다.
3. 전체 선택이 현재 페이지·로드된 항목·필터 결과 전체 중 무엇인지 명시한다.
4. 필터 변경 후 숨은 선택을 유지할지 초기화할지 과업에 맞춰 결정한다.
5. 유지하면 숨은 선택 개수와 전체 해제 경로를 보여주고 조용히 명령 범위를 확장하지 않는다.
6. 전체 결과 선택은 선택 시점의 고정 집합인지 실행 시점의 질의 결과인지 구분한다.
7. 데이터가 실시간 변하면 대상 재확인·선택 스냅샷 등 제품이 지원하는 방식을 선택한다.
8. 개체 삭제·권한 변경·실행 불가 상태를 선택 수와 처리 가능 수에 반영한다.
9. 일괄 작업 전에 대상 집합·제외된 항목·명령 범위를 명령 설계에 전달한다.

## 4. 필터와 탐색의 대화를 설계한다

- 검색어, 정렬, 패싯, 범위, 선택을 섞지 말고 각 조작이 무엇을 바꾸는지 정한다.
- 여러 필터의 AND/OR 결합과 선택 수의 의미를 표시 방식과 일치시킨다.
- 결과에서 제외하는 필터와 맥락을 남기는 강조를 구별한다.
- 조절 결과가 빠르고 비용이 낮으면 즉시 갱신을 우선 검토한다.
- 요청이 비싸거나 여러 조건을 한 번에 조정해야 하면 명시적 적용 버튼을 비교한다.
- 지연 중에는 현재 컨트롤과 표시 결과가 같은 질의인지 알 수 있게 한다.
- 새 조건의 결과가 아직 없는데 이전 결과를 새 결과처럼 제시하지 않는다.
- 활성 조건을 찾고 개별 해제·전체 초기화를 할 수 있게 한다.
- 빈 결과는 데이터 자체가 없다는 결론과 구분하고 조건을 완화할 경로를 제공한다.

## 5. 데이터 질문과 인코딩을 연결한다

| 질문 | 우선 검토할 표현 | 확인할 의미 |
|---|---|---|
| 정확한 값이 얼마인가 | 표·값 라벨·세부 정보 | 단위·정밀도·누락값·집계 범위 |
| 시간에 따라 어떻게 변하는가 | 시간축 추세 | 시간대·간격·집계 주기·관측 공백 |
| 항목 간 크기가 어떻게 다른가 | 공통 기준의 위치·길이 비교 | 축과 기준선이 차이를 과장하지 않는가 |
| 공간적으로 어디에 있는가 | 지도와 위치 기반 탐색 | 위치 정밀도·분포·겹침의 의미 |
| 관계·계층이 어떻게 연결되는가 | 관계·계층 구조와 상세 | 연결의 방향·종류와 탐색 규모 |

- 색·크기·위치·형태가 각각 어떤 속성을 뜻하는지 정한다.
- 색만으로 범주나 상태를 전달하지 말고 라벨·형태 등 다른 단서를 제공한다.
- 길이로 양을 비교할 때 기준선이 같아야 하는지 검사하고 절단 축은 해석 영향을 드러낸다.
- 누락과 0, 측정값과 추정값, 원시값과 집계값을 같은 표시로 합치지 않는다.
- 이상치를 숨기거나 축 범위를 바꾸는 선택에는 사용자 질문과 손실 정보를 기록한다.

## 6. 여러 뷰의 비교와 연동을 정한다

- 같은 데이터의 선택은 각 뷰의 안정적 식별자로 연결한다.
- 집계 수준이 다르면 한 점이 여러 개체를 뜻하는 관계를 명시한다.
- 한 뷰에서 선택·필터가 다른 뷰의 강조인지 제외인지 각각 정한다.
- 작은 반복 차트는 축·척도·순서·포맷을 맞춰 의미 있는 차이만 남긴다.
- 패널마다 별도 척도가 필요하면 그 사실을 표시하고 절대 크기 비교를 유도하지 않는다.
- 여러 시계열은 공통 시간축의 정렬된 패널을 먼저 비교한다.
- 서로 다른 축을 겹치면 시각적 동행을 인과나 동일 크기로 해석할 위험을 명시한다.
- 전체 맥락과 확대된 초점 사이를 오갈 수 있고 현재 범위를 알 수 있게 한다.
- 정확한 값은 hover만이 아니라 키보드·터치·대체 표 등 적절한 경로로 확인할 수 있게 한다.

## 실패모드와 수정 방향

- 숨은 선택까지 실행되어 대상 오해: 선택 수명과 전체 선택 범위를 재정의한다.
- 정렬·필터가 페이지마다 다른 의미: 전체 집합과 로컬 집합의 계약을 드러낸다.
- 표와 지도 결과가 불일치: 질의 버전·개체 식별자·집계 수준을 확인한다.
- 그래프마다 축이 달라 차이를 과장: 공통 척도를 쓰거나 독립 척도를 명시한다.
- 진행 중 갱신이 행을 움직여 오조작: 적용 시점을 분리하고 변경 알림을 제공한다.
- 정확한 값이 포인터에서만 보임: 다른 입력 방식과 정적 값 확인 경로를 보강한다.

## 검증

1. 특정 항목 찾기와 서로 다른 두 항목 비교를 대표 데이터로 수행한다.
2. 필터·정렬·페이지 변경 뒤 선택 집합과 현재 상세의 일치 여부를 확인한다.
3. 일부 항목 삭제·추가·권한 변경 시 표시 수와 실행 대상이 어떻게 바뀌는지 검사한다.
4. 0·누락·극값·같은 값·긴 라벨이 표현 의미를 바꾸지 않는지 확인한다.
5. 다중 뷰에서 같은 선택과 질의가 같은 개체·범위를 가리키는지 확인한다.
6. 지연·실패 상태의 일치는 상태 검토(`ux-state-review`)에 필요한 시나리오만 인계한다.
7. 실제 동작 증거가 필요할 때 브라우저 검증(`browser-e2e-review`)을 연결한다.
8. 정적 시안·표본·실행한 전체 결과를 구분하고 미확인 데이터 범위를 남긴다.

## 결과

- 주 과업·질문, 데이터 범위·단위·식별자와 확인하지 못한 의미.
- 선택한 표현·상세·로딩 구조, 대안과 선택을 바꿀 조건.
- 정렬·필터·선택 집합·복귀·실시간 갱신의 계약.
- 차트 인코딩·척도·집계와 뷰 사이의 연동 규칙.
- 검증 증거, 오해 위험, 미검증 항목과 다음 담당 영역.
