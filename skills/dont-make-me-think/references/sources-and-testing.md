# 근거와 사용자 테스트

## 출처와 적용 범위

이 스킬은 Steve Krug의 책을 바탕으로 만든 독립적인 실무용 리뷰 절차다. 저자의 공식 스킬이나 인증 체계가 아니다.

- [O'Reilly의 *Don't Make Me Think!: A Common Sense Approach to Web Usability, Second Edition*](https://learning.oreilly.com/library/view/dont-make-me/0321344758/): 정식 접근 권한으로 Introduction과 1–12장을 읽고 기존 절차와 대조했다. 원문은 스킬에 복사하지 않고 실행 가능한 원칙만 요약했다.
- [저자의 책 소개](https://sensible.com/dont-make-me-think/): *Revisited* 판의 범위와 후속 판본을 확인할 때 사용한다.
- [저자가 공개한 Revisited 목차](https://sensible.com/downloads/DMMT-Revisited-TableOfContents.pdf): 모바일과 후속 판본의 주제 구성을 확인한다. 목차만으로 상세 주장이나 수치 기준을 입증하지 않는다.
- [저자가 공개한 4장 샘플](https://sensible.com/downloads/DMMT-Revisited-sample-chapter.pdf): 클릭 수보다 선택의 어려움과 불확실성을 보라는 원칙을 공개 자료로 확인한다.
- [저자의 테스트 자료 모음](https://sensible.com/download-files/): 실제 사용자 테스트를 설계할 때 최신 진행 스크립트와 관찰자 자료를 확인한다. 파일을 스킬에 복사해 배포하지 않는다.

### 장별로 반영한 핵심

- 1장: 페이지를 가능하면 자명하게, 불가하면 최소한 빠르게 설명되게 만들고 불필요한 의문을 제거한다.
- 2장: 사용자는 정독보다 훑어보기, 최적화보다 첫 번째로 그럴듯한 선택, 완전한 이해보다 시행착오로 진행한다.
- 3장: 중요도·그룹·포함 관계가 보이는 계층, 익숙한 관례, 명확한 영역, 클릭 단서, 낮은 시각 소음을 점검한다.
- 4장: 클릭 수보다 각 선택의 명확성과 진행 중 확신, 잘못 골랐을 때의 비용을 본다.
- 5장: 정보 없는 환영·자기칭찬 문구와 장황한 지침을 줄이고 자가설명형 UI를 우선한다.
- 6장: 지속 내비게이션, 페이지 이름, 현재 위치, 검색, 하위 계층과 깊은 페이지의 독립적인 길 찾기를 본다.
- 7장: 홈·랜딩 화면은 정체성, 가치, 제공 범위, 시작점과 제품에 해당하는 검색·가입·로그인 진입점을 큰 그림 안에서 설명해야 한다.
- 8장: 개인·직무 취향, 이해관계자 간 충돌, “평균 사용자” 가정을 특정 사용자·과업·맥락의 관찰 가능한 질문으로 바꾸고 작은 테스트로 논쟁을 푼다.
- 9장: 포커스 그룹과 사용성 테스트를 구분하고, 작고 이른 반복 관찰을 큰 막판 연구보다 우선한다.
- 10장: 숨긴 비용·지원, 불필요한 수고, 가식적 배려가 사용자의 호의를 소진하는지 보고 정직한 도움과 복구로 신뢰를 회복한다.
- 11장: 접근성은 사용성의 전제다. 자동 검사와 실제 접근을 구분하고 의미 구조, 라벨, 대체 텍스트, 건너뛰기, 키보드, 읽기 순서를 확인한다.
- 12장: 상사·이해관계자의 위험한 요구를 절대 금지로 맞서기보다 그 뒤의 목적을 찾고 더 나은 대안을 제시한 뒤 실제 테스트로 판단한다. 과도한 개인정보 요구와 시각적 연출은 이 원칙을 적용하는 사례다.

2판의 구체적 사이트, Flash, 이미지맵, 정확한 배치나 단어 수 같은 역사적 예시는 현재 제품의 고정 규칙으로 사용하지 않는다. 현재 플랫폼 관례와 접근성 표준에 맞춰 원칙을 적용한다. 뷰포트 예시, S1–S3, 발견 사항 형식, 근거 상태, 재검증 절차는 이 스킬에서 정한 운영 방식이다. 이를 책의 직접 인용, 공식 점수표 또는 검증된 전환율 개선 공식으로 제시하지 않는다.

책의 특정 문장이나 장별 내용을 정확히 대조해 달라는 요청에는 정식으로 제공된 원문을 다시 확인하고 확인 범위만 설명한다. 장문의 원문이나 책을 대체하는 재구성은 포함하지 않는다.

## 실제 사용자 검증이 필요한 경우

두 표현 중 어느 것이 이해하기 쉬운지, 첫 행동을 찾을 수 있는지, 팀의 디자인 논쟁 중 무엇이 실제로 작동하는지처럼 화면 관찰만으로 결정하기 어려운 문제에 적용한다. 포커스 그룹은 욕구·의견·가치 제안을 탐색할 수 있지만, 한 사람씩 과업 수행을 관찰하는 사용성 테스트를 대신하지 않는다.

큰 막판 연구를 기다리기보다 이른 단계부터 작은 반복 테스트를 계획한다. 책의 저비용 반복 방식에서는 한 라운드에 3–4명을 권장하지만, 제품의 위험도와 연구 목적에 맞게 조정하며 통계적 증명을 위한 표본 수로 사용하지 않는다. 완벽한 대표 참가자를 구하느라 늦추지 말고 대상 사용자와의 차이를 기록한 뒤 결과를 그 조건에 맞게 해석한다.

1. 해당 제품의 대상 사용자와 의미 있는 과업을 정한다. 경쟁 제품, 스케치, 와이어프레임, 프로토타입, 실제 화면 어느 단계에서도 시작할 수 있다. UI 라벨이나 클릭 경로를 정답처럼 알려주지 않는다. 예: “다음 주 예약을 다른 날로 바꾸고 변경됐는지 확인해 주세요.”
2. 처음 보는 화면에서 무엇을 할 수 있을 것 같은지 설명하도록 한다. 진행을 유도하는 힌트 없이 첫 선택과 예상 결과를 관찰한다.
3. 과업을 수행하며 생각을 말하도록 요청한다. 진행자는 중립적으로 듣고, 멈췄을 때만 “지금 무엇을 생각하고 있나요?”처럼 유도하지 않는 질문을 사용한다.
4. 어느 문구에서 멈췄는지, 무엇을 잘못 예상했는지, 첫 번째로 그럴듯한 경로가 무엇이었는지, 도움이나 되돌아가기가 필요했는지를 기록한다. 관찰자도 각자 가장 심각한 문제를 소수로 적는다.
5. 관찰된 행동, 참가자의 의견, 팀의 해석을 구별한다. 참가자의 표현은 실제 기록이 있을 때만 인용한다. 새 기능 요청을 곧바로 요구사항으로 만들지 말고 그 요청 뒤의 막힌 과업을 확인한다.
6. 세션 직후 관찰자와 가장 심각한 문제부터 합의한다. 쉬운 잔수정이 큰 문제를 밀어내지 않게 하고, 추가 설명보다 불필요한 요소를 제거하거나 선택을 명확히 하는 해결책을 먼저 검토한다.
7. 사용자가 문제를 즉시 알아차리고 도움 없이 빠르게 회복하며 불쾌감이나 후속 위험이 없다면 낮은 우선순위로 둘 수 있다. 그렇지 않으면 “결국 성공했다”만으로 문제를 무시하지 않는다.
8. 수정했다면 가능할 때 같은 과업과 조건으로 다시 테스트한다. 재모집이나 실행이 불가능하면 재검증 계획과 미확인 범위를 남긴다. 적은 수의 정성적 관찰을 전체 사용자의 성공률이나 선호도로 일반화하지 않는다.

테스트 진행 자체를 요청받았을 때 공식 자료 모음에서 최신 스크립트를 열어 필요한 절차를 확인한다. 휴리스틱 리뷰만 요청받았다면 참가자 모집, 녹화, 테스트 예약을 시작하지 않고 보고서에 “테스트 제안”으로 남긴다.
