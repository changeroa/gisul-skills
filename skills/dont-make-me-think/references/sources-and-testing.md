# 근거와 사용자 테스트

## 출처와 적용 범위

이 스킬은 Steve Krug의 *Don't Make Me Think, Revisited*를 바탕으로 만든 독립적인 실무용 리뷰 절차다. 저자의 공식 스킬이나 인증 체계가 아니다. 근거로 확인한 공개 자료는 아래 책 소개, 목차, 4장 샘플이다. 책 전체를 열람·대조했다고 주장하지 않는다.

- [저자의 책 소개](https://sensible.com/dont-make-me-think/): 기준으로 삼은 Revisited 판과 책의 범위를 확인할 때 사용한다.
- [저자가 공개한 Revisited 목차](https://sensible.com/downloads/DMMT-Revisited-TableOfContents.pdf): 명확성, 훑어보기, 선택, 문구, 내비게이션, 첫 진입, 사용성 테스트, 모바일, 배려, 접근성이라는 주제 구성을 확인했다. 목차는 각 장의 상세 주장이나 수치 기준을 입증하지 않는다.
- [저자가 공개한 4장 샘플](https://sensible.com/downloads/DMMT-Revisited-sample-chapter.pdf): 클릭 횟수 자체보다 선택의 어려움과 불확실성을 살피고, 도움이 필요할 때 짧고 적절한 위치에 안내를 제공한다는 판단의 근거다. 반복 경로나 로딩 지연처럼 클릭 수가 실제 부담이 되는 경우도 고려한다.
- [저자의 테스트 자료 모음](https://sensible.com/download-files/): 실제 사용자 테스트를 설계할 때 최신 진행 스크립트와 관찰자 자료를 확인한다. 파일을 스킬에 복사해 배포하지 않고 공식 페이지를 연결한다.

뷰포트 예시, S1–S3, 발견 사항 형식, 근거 상태, 재검증 절차는 이 스킬에서 정한 운영 방식이다. 구체적인 UI 점검 항목은 위 주제들을 실제 화면 리뷰에 적용한 해석이다. 이를 책의 직접 인용, 공식 점수표 또는 검증된 전환율 개선 공식으로 제시하지 않는다.

책의 특정 문장이나 장별 내용을 정확히 대조해 달라는 요청에는 해당 원문이나 정식으로 제공된 자료를 확보하고 확인한 범위만 설명한다. 장문의 원문이나 책을 대체하는 재구성은 포함하지 않는다.

## 실제 사용자 검증이 필요한 경우

두 표현 중 어느 것이 이해하기 쉬운지, 첫 행동을 찾을 수 있는지처럼 화면 관찰만으로 결정하기 어려운 문제에 적용한다. 아래는 이 스킬의 짧은 테스트 설계이며 실제 참가자 관찰을 대신하지 않는다.

1. 해당 제품의 대상 사용자와 의미 있는 과업을 정한다. UI 라벨이나 클릭 경로를 정답처럼 알려주지 않는다. 예: “다음 주 예약을 다른 날로 바꾸고 변경됐는지 확인해 주세요.”
2. 처음 보는 화면에서 무엇을 할 수 있을 것 같은지 설명하도록 한다. 진행을 유도하는 힌트 없이 첫 선택과 예상 결과를 관찰한다.
3. 과업을 수행하며 말로 생각을 표현하도록 요청한다. 어느 문구에서 멈췄는지, 무엇을 잘못 예상했는지, 도움이나 되돌아가기가 필요했는지를 기록한다.
4. 관찰된 행동과 참가자의 의견을 구별한다. 참가자의 표현은 실제 기록이 있을 때만 인용한다. 적은 수의 정성적 관찰을 전체 사용자의 성공률이나 선호도로 일반화하지 않는다.
5. 과업을 막는 문제부터 수정하고 관련 과업을 다시 확인한다. 실제 테스트를 수행하지 않았다면 보고서에는 “테스트 제안”으로 표시한다.

테스트 진행 자체를 요청받았을 때 공식 자료 모음에서 최신 스크립트를 열어 필요한 절차를 확인한다. 휴리스틱 리뷰만 요청받았다면 참가자 모집이나 테스트 예약을 시작하지 않는다.
