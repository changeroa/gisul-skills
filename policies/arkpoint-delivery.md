# ARK Point delivery

Use the project/team/templates in the matching project record. Do not route agent
environment maintenance here unless the user explicitly chooses this project.

Deliver the agreed user outcome. A merge is not delivery. Keep deployed work in
the verifying stage while required user-flow checks remain. Re-read changed
requirements before closing. A decision issue may close independently of its
implementation children once the decision and links are recorded.

Write short outcome-first issues with relevant acceptance and source links.
Notification routing is in the project record: no manual Slack sends. Existing
team completion/cancellation and project update/comment notifications must not be
duplicated. Do not send test messages or change notification settings incidentally.

Repository mapping and GitHub merge automation have not been verified by this
configuration. Read actual issue/PR/repository links instead of guessing them.
